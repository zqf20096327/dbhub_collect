## 🚀 安装与运行

### 下载预构建版本

访问官网 `https://storymoss.top` 或 GitHub Releases 页面，下载对应平台安装包后直接安装即可。

### 从源码运行

需要安装 [Node.js](https://nodejs.org/)（推荐 20 LTS）和 [Rust](https://rustup.rs/)。
仓库通过 `rust-toolchain.toml` 固定 Rust 版本为 **1.95.0**，`rustup` 会自动下载对应工具链。

```bash
# 1. 克隆仓库
git clone https://github.com/91zgaoge/StoryMoss.git
cd StoryMoss

# 2. 安装前端依赖
cd src-frontend && npm install

# 3. 安装 Tauri CLI 并运行桌面应用
cd ..
npm install -g @tauri-apps/cli
cargo tauri dev
```

> **注意**：`Cargo.lock` 已纳入版本控制。如需升级依赖，请在本地验证 `cargo clippy` / `cargo test` 通过后再提交。

### 仅运行前端（开发调试）

```bash
cd src-frontend
npm run dev
```

然后在浏览器打开 `http://localhost:5173/`。

### 构建官网落地页

```bash
cd landing
npm install
npm run build
```

构建产物位于 `landing/dist/`，可部署到任意静态托管服务。开发模式运行 `npm run dev`，测试运行 `npm run test`。

### v0.99.0 · 续写训练「跨章复制/原地踏步」根修

- **问题**：10 章训练报告中第 14–17、20 章整段复制上一章，剧情原地踏步，文风漂移并自创「引魂蛆/骨刺」等玄幻设定。
- **根因**：并行批量中修订轮熔断后，兜底取稿按「黑板任意最新稿」取到了下一章；第 n 章被装配成第 n+1 章正文，相邻章因此字节相同（13/14、16/17、19/20），draft 11/15/18 从未落库。报告里的承接断裂大多是这条错位链，不是模型幻觉。
- **结果**：兜底取稿与修订兜底都只接受本章草稿；训练新增 5 条写作红线（设定/语体/推进/承接/设定白名单）、资产重建逐章梗概首尾兜底、跨章复制判「不可用」、质量门逐章单一归类；正文首行章名统一裁掉。

### v0.98.9 · 修复任务进度与执行日志显示不一致

- **问题**：任务详情头部进度已到 40%，展开的「执行日志」最新一条仍停在「进度 5%」；续写训练页的「最新日志」同样不刷新。
- **根因**：任务列表每 5 秒轮询，日志查询却只在任务完成/失败/取消时刷新；运行中的 `task-progress` 事件没有前端消费者，日志面板一直停留在展开时刻。
- **结果**：每个进度事件同时刷新任务列表与对应日志，日志随 5% → 20% → 30% → 40% 等阶段实时推进，并与头部进度、更新时间一致。

### v0.98.8 · 修复日志自动上传提议从未触发（三处日志布局不匹配）

- **问题定位**：官网日志包列表连续多日为空，本机在 11-11 手动上传后不再出现新包；排查发现自动提议从未执行到打包——诊断日志写在 `应用数据/logs/` 子目录，代码却在应用数据根目录找日志。
- **三处根因**：扫描目录少了 `logs/`；轮转文件名是 `storymoss.YYYY-MM-DD`（旧规则只认 `storymoss.log` 前缀）；生产日志是 JSON（`"level":"ERROR"`，旧规则只认纯文本 ` ERROR `）。
- **结果**：错误计数在真实环境恒为 0，自动弹窗永远不会出现；修复后本机 11-17 日志的 70 条 tracing ERROR 与 30 条工作流 ERROR 都能被识别，满足条件时启动即会询问是否上传诊断日志。

### v0.98.7 · 续写训练报告驱动修复：连续承接、质检可信与风格 DNA 注入

- **每章承接上一章，不再「续前前章」**：批量续写时质量门与下一章 writer 并发，上一章尚未装配进正文库；旧逻辑会从 DB 读到 n-2 章。现在在途上一章的正文与大纲显式进入下一章 writer 与章纲规划，训练 10 章连续承接同一现场/人物/未完结事件。
- **质检不再「熔断后假装通过」**：编辑审计增加轮数与输出额度，输入内嵌时直接裁决 JSON，裁断输出可补括号解析；批量 deadline 按章数放大。报告区分真实通过、修订与质检降级，不再出现「10 章通过」与逐章 7 章 revise 的矛盾。
- **风格 DNA 真正生效**：续写 prompt 现在注入 StyleDNA 六维指标（此前只绑定不进 prompt），文笔有可执行的句式/用词/对话约束。
- **幻觉不再回流放大**：训练沙盒关闭生成正文的资产 ingest，指令携带原文权威人物名册；上一轮编审建议按上下文接地过滤，并把「真实后续节点」沉淀给下一轮主线对齐。

### v0.98.6 · 修复发布门禁重跑缺陷，恢复 macOS 公证与发布

- **重跑不再被 nightly tag 误拦**：docs-guard 只与上一个稳定 tag 比较，`vX.Y.Z-nightly` 不再参与 `PREV` 选择；此前 nightly 与稳定 tag 指向同一 commit 时 diff 为空，会误判「必需文档未更新」。
- **macOS 公证恢复**：Apple Developer Program 协议续签后重新触发 macOS 签名/公证与全平台打包、官网同步与 updater 校验。

### v0.98.5 · 训练源章节缓存 + 栗子读书 MCP 读竞态修复

- **反复训练不再重复取章**：MCP 源章节按「服务器 + 书 + 章号」缓存到本地 SQLite；第一次训练取章并回写，后续训练直接命中缓存，日志显示命中/新读数量。取章更省时，也不再反复触碰回环 HTTP。
- **配套栗子读书 v0.14.26**：服务端在 accept 后清除客户端 socket 继承的 `O_NONBLOCK`，header/body 分次到达时不再立即返回 400「请求不完整」；分离写入 1–500ms 实测全部成功。

### v0.98.4 · 续写训练取章不再被栗子读书「请求不完整」中断

- **取章竞态可自愈**：Legado MCP 在 TCP 连接建立后立即读取请求，客户端若在连接与写请求之间被调度延迟（本机 LLM 高负载时偶发），body 未到达就会返回 400「请求不完整」。现在这类拒绝被识别为「JSON-RPC 尚未解析、工具未执行」，回环请求会安全重发一次；只读工具另有退避重试，写工具不会重复执行副作用。
- **训练不再在第 136/137 章中途判死**：同一本书连续取 20 章、风格/资产重建、续写与编审链路可继续推进。

### v0.98.3 · 训练风格 DNA 与资产重建适配推理模型

- **JSON 截断可修复**：风格分析 JSON 中途被截断时，自动补全未闭合括号并采用已生成字段；两次尝试仍不完整才降级。
- **思维链里的 JSON 可用**：推理模型（如 deepseek-v4）把答案留在 `reasoning_content`、正文为空时，结构化任务（资产重建/风格分析）会从思维链提取最终 JSON；普通写作请求仍不会把思维链当正文。
- **不再空手重建**：资产重建提高输出额度并启用 JSON mode，世界观/大纲/角色/关系不再因一次空响应整段丢失。

### v0.98.2 · 续写训练 10 章不再被 token 预算中途熔断

- **长批量训练不再中途判死**：run 级 token 硬熔断已暂停（`AgencyBudget::check()` 恒放行），10 章批量续写不会在 gate（编辑审计）阶段因累计 30 万 token 报「预算耗尽」而整批失败；token 用量仍照常记账，运行检查点与成本观测不受影响。

### v0.98.1 · 本地书籍训练的取章起点修复

- **固定起点不再跳过首章**：本地 epub/txt 作为训练源时，起始章号现在按 1-based 正确转换为 0-based 切片起点；此前「从指定章连取」会跳过指定章本身并整体错一位。默认（第 1 章起）与 MCP 源不受影响。

### v0.98.0 · 续写训练升级：连续续写 10 章 + 编审 Agent 全面对比

- **一次训练写 10 章**：续写训练默认连续续写 **10 章**（可在训练页配置 1–20 章），上下文默认 10 章；沙盒按章号连续承接，不再只写 1 章。
- **编审 Agent 对照原书后 10 章**：续写完成后调用编审 Agent（`agency_editor_auditor_system`，支持你在工作室自定义的人设），逐章对照原小说后 10 章真实原文，从文笔风格、情节推进、人物口吻、节奏密度、钩子悬念与承接六个维度出具裁决，再做跨章总评（人物弧/冲突升级/线索经营/风格漂移），生成《续写质量分析报告》。
- **报告驱动能力优化**：报告中的低分维度会自动转成下一轮硬性修正——承接失败则强制注入上一章结尾现场锚点（更长窗口），文笔偏低则即使 StyleDNA 已绑定也强制原文风格锚点，钩子/节奏偏低则写入章末钩子与信息密度要求；改进项自动注入下一轮续写指令，形成闭环。
- **报告可视化**：训练报告弹窗新增逐章对比表（沙盒章 / 原书章 / 总分 / 五维 / 承接 / 裁决 / 编审摘要），趋势仍按书聚合、自动跳过评分不可用的轮次。

### v0.97.0 · Gate 裁决只有一个权威，导航与页面清单同源

- **Gate verdict 不再「run 说完成、gate 说失败」**：`editor_gate_records` 增加 `run_id` 成为 run QC 的唯一权威。后台质检无论先于还是晚于 run 收尾完成，都会把最新裁决回填 `run.result.verdict`；batch 逐章回填，不再长期停在 `pending`。
- **导航不再三份清单**：`navigation/views.ts` 统一分组/label/图标/布局标记，`navigation/viewComponents.tsx` 用 `Record<ViewType, ComponentType>` 强制穷举页面映射；新增视图漏页面会 tsc 失败，不再静默落到 Dashboard。Sidebar 与 App 都从同一份 VIEW 清单派生。

### v0.96.1 · 日志巡检首轮修复：生成链路状态不再「永远进行中」

每天自动下载用户日志包的分析机器人发现了两处真实问题并修复：生成链路追踪（Tracing 面板）里的运行记录此前从不落终态，
一半以上的记录永远显示「进行中
