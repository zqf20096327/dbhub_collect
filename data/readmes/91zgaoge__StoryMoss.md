## 🚀 安装与运行

### 下载预构建版本

访问官网 `https://storymoss.top` 或 GitHub Releases 页面，下载对应平台安装包后直接安装即可。

### 从源码运行

需要安装 [Node.js](https://nodejs.org/)（推荐 20 LTS）和 [Rust](https://rustup.rs/)。
仓库通过 `rust-toolchain.toml` 固定 Rust 版本为 **1.95.0**，`rustup` 会自动下载对应工具链。

```bash
# 1. 克隆仓库
git clone https://github.com/91zgaoge/StoryMoss.git
cd StoryMoss

# 2. 安装前端依赖
cd src-frontend && npm install

# 3. 安装 Tauri CLI 并运行桌面应用
cd ..
npm install -g @tauri-apps/cli
cargo tauri dev
```

> **注意**：`Cargo.lock` 已纳入版本控制。如需升级依赖，请在本地验证 `cargo clippy` / `cargo test` 通过后再提交。

### 仅运行前端（开发调试）

```bash
cd src-frontend
npm run dev
```

然后在浏览器打开 `http://localhost:5173/`。

### 构建官网落地页

```bash
cd landing
npm install
npm run build
```

构建产物位于 `landing/dist/`，可部署到任意静态托管服务。开发模式运行 `npm run dev`，测试运行 `npm run test`。

### v0.93.16 · 续写训练不再「另起新故事」，空稿不再冒充正文

真机检查发现两个训练沙盒的续写与前作严重脱节：一轮写出了现代都市「陈默/铜钱」的新故事（与《阴脉先生》第 106 章的桐人镇魇现场无关），另一轮生成正文后又被幕前切书的 `<p></p>` 空文档覆盖。本版修复了根因：

- **基准章泄漏**：训练指令的文风锚点此前取「最后两章」，末位是真实后续基准章（答案），会把基准章末段喂给模型；现在只用上下文章，基准章绝不进入续写指令。
- **硬承接锚点**：训练指令始终携带上一章结尾原文（900 字），并明确「同一地点/同批人物/同一时代、未完结事件先落地，禁止新主角/新委托/新场景」；指令上限由 1200 字提高到 4096 字，锚点不再被截断。
- **过期建议过滤**：上轮训练建议只在承接区间重叠时采用，跨章节区间（如第 1–10 章的建议）不再污染第 97 章之后的续写。
- **资产缺失兜底**：沙盒无世界观/角色卡/大纲时，writer 不得输出「无法完成/创作资产为空」拒绝话术；续写管线的散文回退改为「带前文的续写 prompt」，不再复用创世开篇 prompt。
- **空稿守卫**：判分前把 `<p></p>`/空白/拒绝话术判为不可用产出，任务失败且不落假报告；`update_scene` 统一把视觉空 HTML 视为 None，幕前切书空文档不再覆盖已有正文。

### v0.93.15 · 续写训练不再被一次网络抖动判死

真机训练在连续取章时遇到栗子读书回环 HTTP 的一次 `Connection reset`，整条训练任务直接失败。现在只读工具调用遇到这类瞬时传输故障会自动重试两次（写工具绝不重发，避免重复副作用），单次抖动不再毁掉整轮训练。同时修复训练报告的「假 0.00」：判官返回缺失五维评分时不再落库成 0.00 假报告，而是先重试判官；仍不可用则存「评分不可用」降级报告，趋势图跳过这一轮。报告里也标清「沙盒第 N 章（对应真实第 M 章）」，不再把沙盒章号与真实章号混在一起。

### v0.93.14 · 任务进度和日志时间终于对齐了

任务页此前会出现「进度已经更新，日志时间却停在几分钟前」的情况：进度、日志、心跳分三处独立写入。现在每次进度更新会用同一个时间戳同时写入进度、心跳与一条日志，毫秒级一致。界面上的最近更新、上次运行、心跳与每条日志也都改成完整本地日期时间，诊断页不再直接截取 UTC 字符串。风格学习与训练报告页同步受益。

### v0.93.13 · Linux AppImage 打包不再被外部下载拖垮

AppImage 打包工具（AppRun / linuxdeploy）需要从 GitHub Releases 下载，一次 504 就会让 Linux 构建失败。现在构建前会带多轮重试预热到 `~/.cache/tauri`，命中缓存后 bundler 不再联网。

### v0.93.12 · 续写训练失败不再「白跑」+ 任务状态一眼可见

续写训练连续成功若干轮后，真机出现一种失败：质量门要求修订，主创在修订轮多轮未完成（LLM 熔断），整条管线把首轮草稿一起判死。现在修订轮熔断会保留首轮草稿继续装配，并在「查看任务」里留下完整日志；训练页新增常驻状态横幅——执行中显示进度与最新日志，失败显示错误全文，旁边带「重试」和「查看任务」。任务完成/失败/创建也不再只在任务页才弹提示：全局 toast 带「查看任务」按钮，一键跳到「全部任务」并展开、高亮对应任务行。另修复风格学习偶发整份作废：模型把平均句长写成小数（`22.6`）也会被宽容解析。

### v0.93.11 · 外部下载抖动不再误红构建

macOS 构建需要的 protoc 从 GitHub Release 下载时偶发 504，一次网络抖动就会让整个 tag 构建变红。现在 protoc 安装会在失败后自动重试两次，并验证二进制真正可用；重试耗尽才失败。

### v0.93.10 · 发布门禁不再「红着照发」

修掉了发布流程的一个漏洞：tag 构建的文档/版本检查失败后，打包与官网上传仍会继续。v0.93.8 就曾把 0.93.7 的安装包当作新版本传上去。现在 `docs-guard` 会同时校验 tag 与四处版本号一致，失败时直接拦住打包、GitHub Release 与官网上传。

### v0.93.9 · 「任务」成了一级菜单，训练与分析工具归位

幕后侧栏的「任务」从运维子项提升为一级菜单，排在「创作」之后，下面直接收纳四项：全部任务、拆书、指导书提炼、续写训练。此前拆书在创作组、续写训练在分析组（还默认折叠）、指导书提炼只能进拆书页再点页签；现在四个入口一屏可见，点「指导书提炼」直接落在对应页签，页内页签切换也会同步侧栏高亮。

### v0.93.7 · 风格学习不再因小错全废

二轮训练分析抓到风格学习失效的真根因：模型返回的风格画像只缺一个字段就整份作废。现在缺失部分自动回退默认值，风格学习在真机上稳定生效；训练的「立即跑」也会复用同书任务行，不再反复堆积。

### v0.93.5 · 续写更会「接着写」了

用你本机的续写训练报告做了一次质量评估：首轮 0.32 分，主因是 AI 会跳过上一章结尾没写完的场景另起炉灶，以及风格学习静默失败后完全没有文风参照。现在续写指令强制「紧接前文末尾现场、未完结事件先落地」；风格分析失败时自动改用原文章节末尾节选做文风锚点。服务端日志上传接口也修了编译问题。

### v0.93.4 · 代理工作室错误可追溯，修订熔断不再丢稿

代理工作室的任务失败现在会以 ERROR 级写入应用日志（连同导演派发了什么），日志页上传的分析包能看到完整失败链。修订场景时即使主创多轮没按约定格式写稿，也会自动从黑板取回草稿或降级直出修订文，不再整轮失败报「黑板无修订稿」。模型端点闪断会先重试一次再切换候选。日志上传免登录：检测到新错误日志时自动打包并弹窗询问，同意才上传（拒绝则当天不再提示）。

### v0.93.3 · 导出不再乱码，幕后切书即点即达

修好了小说导出的老大难：EPUB 现在严格按幕前阅读排版（衬线、两端对齐、首行缩进 2em），PDF 内嵌思源宋体（Noto Serif SC）并只打包用到的字形——中文清晰、体积可控，段落/对话不再出现字面 `</p><p>` 和 ``` 残留；MD/HTML/TXT 同步走统一的段落规范化。同时修掉「幕后点另一本书，幕前停在旧书旧章」的死端：切书前的保存等待有 5s 上限、保存失败不再卡死切换、切换未落地自动重试——点了哪本，幕前就是哪本的最新章。

### v0.93.2 · 训练任务融入任务系统，不再重复占资源

续写训练的计划与运行历史现在统一在幕后「运维 → 任务」页管理：同一本书的训练任务只保留一行，「立即跑一轮」会先把当前配置同步进计划再触发，不再反复堆积一次性任务行。任务页能给训练任务显示中文类型标签，跑完后可一键跳转查看训练报告。后台同时修掉了每轮训练泄漏一个轮询协程的问题，并把手动/定时触发的互斥锁真正接通——同一训练任务不会被并发跑两轮。

### v0.93.0 · MCP 自动连接，工具不再逐个填

幕后「设置 → 扩展 → MCP 连接」现在打开即自动扫描并连接已保存的服务器；栗子读书的连接状态、11 个工具、映射版本和权限一屏可见，不需要再手动点连接或逐个选工具。工具目录按服务器分组展示，添加服务器改成弹窗；续写训练页会自动选服务器、自动选 `get_chapter_content` 并生成参数（`book_url` 自动解析）。

### v0.92.0 · 学习回路与叙事数据接入主工作流

你在学习中心批准的写作模式（instinct）现在会直接注入主创的写作提示词（可在设置里关掉）；学习技能可以被四个 agent 通过 `skill_execute` 调用；设置页的写作策略（冲突强度/节奏/AI 自由度）对续写生效。同时，叙事分析的场景节奏、追读债账本会回流到写作上下文，导演巡检也能看到这些数据洞察；修订章节后会自动重新提取知识图谱。

### v0.91.1 · 栗子读书 MCP 真正可用（映射契约 v1）

栗子读书的 MCP 工具现在能出现在 MCP 页并可执行：标准 `inputSchema` 兼容、回环请求绕过系统代理与 reqwest 分次写、11 个工具（含联网搜索）完整列出。新增映射契约 v1：协议/源版本白名单、字段漂移与源权限变化分别定义整机失效/单工具失效/权限撤销，查询返回稳定的 `MCP_*` 错误码，而不是静默 0 工具。

### v0.91.0 · 把孤岛接回导演

级联中心现在可以把整批改稿影响「交给导演」；任务页新增「代理任务」页签，可对导演派发的子任务重试/取消；场景编辑器与场景快捷操作（AI 续写/修改）也改为预填导演指令，不再有占位提示。导演巡检还能看到未结清质量债，并可真实登记新债。

### v0.90.0 · 主工作流第一次真正「被看见」

代理工作室的导演/管理/编审/主创运行现在会出现在「生成链路」页：每次 run 一条 trace，能看到各个角色调用的步骤与耗时。仪表盘「代理运行」直接读活跃运行，可一键发起四角色创世；「数据洞察」新增角色用量卡，分别统计主创/管理/编审/导演的调用次数、tokens 与费用。

### v0.89.9 · 任务页与叙事功能在安
