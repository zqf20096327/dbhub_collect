## 🚀 安装与运行

### 下载预构建版本

访问官网 `https://storymoss.top` 或 GitHub Releases 页面，下载对应平台安装包后直接安装即可。

### 从源码运行

需要安装 [Node.js](https://nodejs.org/)（推荐 20 LTS）和 [Rust](https://rustup.rs/)。
仓库通过 `rust-toolchain.toml` 固定 Rust 版本为 **1.95.0**，`rustup` 会自动下载对应工具链。

```bash
# 1. 克隆仓库
git clone https://github.com/91zgaoge/StoryMoss.git
cd StoryMoss

# 2. 安装前端依赖
cd src-frontend && npm install

# 3. 安装 Tauri CLI 并运行桌面应用
cd ..
npm install -g @tauri-apps/cli
cargo tauri dev
```

> **注意**：`Cargo.lock` 已纳入版本控制。如需升级依赖，请在本地验证 `cargo clippy` / `cargo test` 通过后再提交。

### 仅运行前端（开发调试）

```bash
cd src-frontend
npm run dev
```

然后在浏览器打开 `http://localhost:5173/`。

### 构建官网落地页

```bash
cd landing
npm install
npm run build
```

构建产物位于 `landing/dist/`，可部署到任意静态托管服务。开发模式运行 `npm run dev`，测试运行 `npm run test`。

### v0.98.1 · 本地书籍训练的取章起点修复

- **固定起点不再跳过首章**：本地 epub/txt 作为训练源时，起始章号现在按 1-based 正确转换为 0-based 切片起点；此前「从指定章连取」会跳过指定章本身并整体错一位。默认（第 1 章起）与 MCP 源不受影响。

### v0.98.0 · 续写训练升级：连续续写 10 章 + 编审 Agent 全面对比

- **一次训练写 10 章**：续写训练默认连续续写 **10 章**（可在训练页配置 1–20 章），上下文默认 10 章；沙盒按章号连续承接，不再只写 1 章。
- **编审 Agent 对照原书后 10 章**：续写完成后调用编审 Agent（`agency_editor_auditor_system`，支持你在工作室自定义的人设），逐章对照原小说后 10 章真实原文，从文笔风格、情节推进、人物口吻、节奏密度、钩子悬念与承接六个维度出具裁决，再做跨章总评（人物弧/冲突升级/线索经营/风格漂移），生成《续写质量分析报告》。
- **报告驱动能力优化**：报告中的低分维度会自动转成下一轮硬性修正——承接失败则强制注入上一章结尾现场锚点（更长窗口），文笔偏低则即使 StyleDNA 已绑定也强制原文风格锚点，钩子/节奏偏低则写入章末钩子与信息密度要求；改进项自动注入下一轮续写指令，形成闭环。
- **报告可视化**：训练报告弹窗新增逐章对比表（沙盒章 / 原书章 / 总分 / 五维 / 承接 / 裁决 / 编审摘要），趋势仍按书聚合、自动跳过评分不可用的轮次。

### v0.97.0 · Gate 裁决只有一个权威，导航与页面清单同源

- **Gate verdict 不再「run 说完成、gate 说失败」**：`editor_gate_records` 增加 `run_id` 成为 run QC 的唯一权威。后台质检无论先于还是晚于 run 收尾完成，都会把最新裁决回填 `run.result.verdict`；batch 逐章回填，不再长期停在 `pending`。
- **导航不再三份清单**：`navigation/views.ts` 统一分组/label/图标/布局标记，`navigation/viewComponents.tsx` 用 `Record<ViewType, ComponentType>` 强制穷举页面映射；新增视图漏页面会 tsc 失败，不再静默落到 Dashboard。Sidebar 与 App 都从同一份 VIEW 清单派生。

### v0.96.1 · 日志巡检首轮修复：生成链路状态不再「永远进行中」

每天自动下载用户日志包的分析机器人发现了两处真实问题并修复：生成链路追踪（Tracing 面板）里的运行记录此前从不落终态，
一半以上的记录永远显示「进行中」——现在成功/失败/取消都会正确收尾；保存章节时若遇到已删除或被其它窗口替换的过期章节，
错误提示从「Query returned no rows」改为「目标章节/场景不存在，请刷新目录后重试」，可直接照做。

### v0.96.0 · 未尽债务收口：租约续期、DB 守卫、保存 CAS、入口互锁

v0.95.0 留下的一批状态机债务已逐项收口：

- **租约不再过期失权**：Append/资产租约守卫自带后台续期；进程崩溃留下的过期租约在下次 acquire 前被清理。
- **DB 最后一道防线**：V158 迁移为任务/run/agent task/聊天/审批/gate record 的状态列建触发器，未知状态直接 ABORT，不再静默落库。
- **保存 CAS**：幕前保存携带加载正文的 FNV-1a 指纹；幕后已改正文时拒绝旧快照覆盖，标题/元数据变化不误判。只比对正文，不比对时间戳。
- **入口互锁**：续写与智能输入共享 ref 锁，覆盖意图分类/预检窗口；生成开始后释放，文思 auto-continue 照常。
- **依赖等待显式 waiting**：子任务等父任务不再伪装成 queued；stale 心跳任务在每次派发前被回收。
- **死代码删除**：旧本地 OAuth/JWT session、窗口 closed/hidden 歧义、automation 双 bool、叙事 Falling 不可达、视图布局三处清单。

### v0.95.0 · 隐式状态机治理：状态只有一个所有者，终态不可被覆盖

全仓审计出 51 个隐式状态机（同一事实散落在多个布尔、Option、字符串列、store 与事件中）。本版把同类回归一次性收口到三个核心边界：

- **任务/agency 生命周期**：新增 `lifecycle` 模块的显式转移表与 RAII `CancelHub`；任务完成/失败/进度只允许从 `running` 写入，取消后迟到的执行结果不再复活终态；agency run 只有真正写入 completed 才发完成事件，导演取消同时落 DB；聊天占位消息成功后回填 `done`，审批动作复用同一行 `approved→executing→done`。
- **前端生成协议**：`state/generation.ts` 接线为唯一解释器，后端 `phase` 改为 snake_case id + 中文 `label`，彻底消除「中文/英文终态各判一套」导致的状态栏永久转圈；后台活动聚合改为读取当前 store（旧快照 bug 让优先级守卫失效）。
- **前端文档会话**：章节选择增加 epoch 票据，快速点 A 再点 B 只应用最后一次；Esc 终止打字机、Tab 只在完整输出后接受；跳过正文加载不再留下“保存中”假死；切书失败恢复旧故事事件流。

同时修掉 MCP 无注解工具默认只读导致写工具重发、updater 首源无更新短路、重复日志包返回不存在路径、过期/取消订阅仍解锁、拆书失败后无法重试、风格学习/重算运行集合永久卡死、PostProcess 损坏状态伪装成 Running 等隐式状态。

### v0.94.0 · 续写训练按真实创作流程重建资产，再续写、编审与对比

训练沙盒此前只有灌入的章节正文，没有世界观、故事大纲、角色和关系，writer 很容易拒绝或另起新故事。现在训练会先把取得的上下文章重建为**世界观、故事大纲（含下一节点）、角色卡、角色关系、逐章梗概**，再进入与正作相同的续写管线（writer → 质量门 → 修订 → 装配），而不是从零创世。资产分析只使用前文实际出现的人名/地名，未接地的人名直接跳过；长章保留开场与结尾窗口，末章结尾用于下一节点判断。续写完成后，判官除对比真实后续章，还会看到上一章结尾现场，专门检查 AI 是否紧接现场；报告固定记录「资产重建 → 编审 → 对比」三段流程与本轮资产计数，改进建议继续自动注入下一轮训练。

### v0.93.16 · 续写训练不再「另起新故事」，空稿不再冒充正文

真机检查发现两个训练沙盒的续写与前作严重脱节：一轮写出了现代都市「陈默/铜钱」的新故事（与《阴脉先生》第 106 章的桐人镇魇现场无关），另一轮生成正文后又被幕前切书的 `<p></p>` 空文档覆盖。本版修复了根因：

- **基准章泄漏**：训练指令的文风锚点此前取「最后两章」，末位是真实后续基准章（答案），会把基准章末段喂给模型；现在只用上下文章，基准章绝不进入续写指令。
- **硬承接锚点**：训练指令始终携带上一章结尾原文（900 字），并明确「同一地点/同批人物/同一时代、未完结事件先落地，禁止新主角/新委托/新场景」；指令上限由 1200 字提高到 4096 字，锚点不再被截断。
- **过期建议过滤**：上轮训练建议只在承接区间重叠时采用，跨章节区间（如第 1–10 章的建议）不再污染第 97 章之后的续写。
- **资产缺失兜底**：沙盒无世界观/角色卡/大纲时，writer 不得输出「无法完成/创作资产为空」拒绝话术；续写管线的散文回退改为「带前文的续写 prompt」，不再复用创世开篇 prompt。
- **空稿守卫**：判分前把 `<p></p>`/空白/拒绝话术判为不可用产出，任务失败且不落假报告；`update_scene` 统一把视觉空 HTML 视为 None，幕前切书空文档不再覆盖已有正文。

### v0.93.15 · 续写训练不再被一次网络抖动判死

真机训练在连续取章时遇到栗子读书回环 HTTP 的一次 `Connection reset`，整条训练任务直接失败。现在只读工具调用遇到这类瞬时传输故障会自动重试两次（写工具绝不重发，避免重复副作用），单次抖动不再毁掉整轮训练。同时修复训练报告的「假 0.00」：判官返回缺失五维评分时不再落库成 0.00 假报告，而是先重试判官；仍不可用则存「评分不可用」降级报告，趋势图跳过这一轮。报告里也标清「沙盒第 N 章（对应真实第 M 章）」，不再把沙盒章号与真实章号混在一起。

### v0.93.14 · 任务进度和日志时间终于对齐了

任务页此前会出现「进度已经更新，日志时间却停在几分钟前」的情况：进度、日志、心跳分三处独立写入。现在每次进度更新会用同一个时间戳同时写入进度、心跳与一条日志，毫秒级一致。界面上的最近更新、上次运行、心跳与每条日志也都改成完整本地日期时间，诊断页不再直接截取 UTC 字符串。风格学习与训练报告页同步受益。

###
