# DB-G
[![Listed on Awesome MyGo](https://awesomemygo.dev/badge.svg)](https://awesomemygo.dev/apps/db-g)

对标 [db-k](https://github.com/Kuangcp/DB-K) 的数据库客户端（Go + mygo）。
**已完成与后续规划见 [`Roadmap.md`](Roadmap.md)**

![](/docs/snapshots/Snipaste_2026-11-07_18-05-53.webp)

## 为什么选 DB-G

**一个可执行文件，四个数据源，键盘上一路到底。**

DB-G 是本地优先的桌面数据库客户端：不装运行时、不连云端、不收集数据。下载后双击就是一个完整的 SQL 工作台，连接、查询、改数据、导出全部在本机完成。

- **开箱即用**：Windows / Linux 各一个独立可执行文件，无 Java、无 Electron、无 WebView 运行时；界面原生绘制，冷启动即用。
- **一个窗口四类库**：SQLite、MySQL、PostgreSQL、ClickHouse 共用对象树、补全、结果表格与导出流程，不必在几个客户端之间切换。
- **连接随手开关**：顶栏数据源名双击连接/断开；断开后圆点变灰、已加载的对象树保留，再双击重连并展开。
- **为键盘设计**：`Ctrl+Enter` 执行、`Ctrl+Tab` 切最近控制台、`Ctrl+Q` 看 DDL、`Ctrl+F` 查找，快捷键全部可改绑。
- **大库不卡**：对象按页加载 + 24 小时磁盘缓存，几万个对象也只查当前需要的那一页。
- **结果能干活**：结果钉住对比、单元格编辑单事务提交、JSON 树查看、CSV / JSON / SQL INSERT 导出。
- **数据留在本机**：连接密码 AES-256-GCM 本机加密，日志自动脱敏，无遥测、无账号。

## 下载与运行

Release 页面提供安装包（GitHub / Gitee 均可）：

| 平台 | 文件 | 运行要求 |
|---|---|---|
| Windows x64 | `db-g-setup-<版本>-amd64.exe` | Windows 10 / 11；每用户安装，支持签名自动更新 |
| Linux x64 | `db-g-<版本>-linux-amd64.tar.gz`（含 `install.sh`）或 `db-g_<版本>_amd64.deb` | GTK 3（Arch `gtk3`、Debian/Ubuntu `libgtk-3-0`、Fedora `gtk3`）；归档解压后运行 `sh install.sh` 安装到用户目录 |

配置、日志与控制台文件默认落在 `~/.config/db-g/`（Windows 为 `%AppData%\db-g\`）；
开发构建（`make run` / `make install`，没有 `releaseBuild` 标记）使用独立的 `~/.config/db-g.dev/`。

## 功能清单

- [x] 编辑器：mygo `ui/editor`（SQL 高亮、行号、查找替换 Ctrl+F、折叠、多光标、撤销；
      百万行级视口布局，性能基准见 docs/spike-results.md 的 A1 一节）；
      编辑器/结果分隔线按窗口高度取比例，`Alt+D` 随时隐藏/显示结果区
- [x] M1：打开 SQLite 文件、异步执行 SQL（Ctrl+Enter）、虚拟化结果表格
      （行号/截断徽章/错误横幅/停止取消/500 行与 1MB/16MB 预算）
- [x] M2：主页面布局对齐 db-k 骨架（侧栏/顶栏/单行工具栏）；连接管理
      （JSON 持久化/新建/编辑/删除/状态点）；SQLite 对象树（懒加载）
- [x] 侧栏连接树：文件夹（可嵌套、新建/重命名/删除、同层重名拦截；删除时连接与
      子文件夹上移到父级）、文件夹折叠与子项计数；每个数据源显示对应品牌图标；
      连接行/文件夹行无边框，悬停浅底；**Ctrl+拖动**排序、把连接或文件夹拖入文件夹；
      顶部搜索框按连接名/文件夹名/**已加载对象名**过滤并自动展开命中（只覆盖已加载对象）；
      连接弹窗可选所属文件夹；连接行右键菜单：**复制数据源**（同文件夹生成副本、
      名称自动去重）、**删除连接**（仍需二次确认）
- [x] 大库元数据（对齐 db-k）：先取各对象组计数，展开分组才按页加载（每页 1000、
      单组最多 5000）；查询在后台线程，连接/展开不再同步拉全量对象；
      编辑器补全目录只取前 2000 条，避免 6 万张表把 UI 和补全拖死
- [x] 元数据磁盘缓存（对齐 db-k）：`<config>/db-g/meta/<connID>.json`，24h TTL；
      连接身份指纹一致时展开零查询，过期先用后刷；删除连接、改目标地址、
      手动「重载对象树」会自动清理缓存
- [x] 选区执行：仅执行编辑器选中的 SQL，无选区时禁用（禁止跑整个控制台）
- [x] 查询超时：连接弹窗按数据源配置（秒，空/0 = 默认 30，可设到 24h）；
      超时后主动取消驱动的语句并在结果区显示「查询超时（Ns），已取消」
- [x] 数据源：SQLite / MySQL / **PostgreSQL**（pgx）/ **ClickHouse**（只读优先）
      —— 连接、执行、对象树、列目录（含主键）、补全、导出；四个驱动都实现了对象
      DDL 查看；PostgreSQL / MySQL / ClickHouse 支持顶栏切换 schema/库（MySQL/CK 显示库名，
      PG 显示「库.schema」），切换后补全、DDL、裸表名查询都跟随当前 schema；
      MySQL 连接不填默认库时也能按库惰性加载对象与列目录；
      PostgreSQL 支持写操作，ClickHouse 只读
- [x] 控制台 + 工作区：一个数据源多个命名控制台，每个绑定
      `~/.config/db-g/consoles/<connectionID>-<consoleID>.sql`；标签条/工作区切换、防抖自动落盘、
      Ctrl+S 立即保存、重启恢复工作区与控制台正文/光标。**关闭标签（×）只是移出当前
      工作区，文件保留**；右键「删除…」才删元数据与 .sql。侧栏每个数据源下列出它的
      全部控制台，可重新打开。标签按「数据源 / 控制台」显示（单控制台时省略控制台名），
      放不下的标签收进标签条末尾的 More 菜单，工作区切换器始终可见；**新建控制台只在
      侧栏数据源下的入口**。**按住 Ctrl 拖动标签**调整工作区内顺序；**Ctrl+Tab** 在最近
      使用的两个控制台之间切换（Alt-Tab 式）。
- [x] P1 日常查询闭环：

      「**导出选区**」子菜单导出为 CSV / JSON / SQL INSERT；
      **查看完整内容**：合法 JSON 渲染成可折叠树（键排序、展开/收起、类型着色、

      **取更多**（派生表分页追加）、**导出** CSV / JSON / SQL INSERT

      新执行时 pinned Tab 保留在左、新结果追加到右；切控制台各自保留，重启消失（内存态）；

- [x] M3（部分）：多语句执行 + SQL 历史（语句级进度/gutter 状态已做，历史面板已做）
- [x] P2 写操作（M6）：单表 + 主键的结果可编辑 —— 弹窗改格、增行、删行、撤销；
      提交前逐条参数化 SQL 预览，**单事务**执行，影响行数 ≠ 1 整体回滚；
      JOIN / 视图 / 主键不在结果里 / 别名表达式列一律只读（工具条显示原因）；

- [x] 自动补全（A2）：SQL 关键字/函数/类型 + 当前数据源的表/视图；打字自动弹，
      `Ctrl+Space` 显式触发；表/视图目录按连接缓存（TTL 5 分钟，顶栏「设置」里
      可手动「刷新补全缓存」）；**关键字/类型/函数随数据源方言**（MySQL 的
      AUTO_INCREMENT / ENGINE / GROUP_CONCAT，PostgreSQL 的 RETURNING / SERIAL，
      ClickHouse 的 LowCardinality / DateTime64，SQLite 的 AUTOINCREMENT 等），
      编辑器语法高亮同步使用同一份方言词表；列补全按**光标所在语句/子查询引用的表**提示
      （FROM · JOIN · UPDATE · INTO，支持多表 JOIN、别名与 CTE 展开；**函数/表达式
      括号内（sum、avg、coalesce、WHERE (…)）也照常补列**；语句里没有表时不出列）；
      FROM/JOIN/UPDATE/INTO 后正在写表名时优先提示表/视图；相邻语句漏写分号时，
      补全按行首 `SELECT`/`INSERT` 等关键字隔开，不会把下一条语句的表混进当前补全
- [x] 内联 AI 补全：编辑器里按 `Alt+\` 或点工具条「AI 补全」，按当前语句/光标上下文请求模型；

- [x] AI 助手（第一阶段）：右侧可折叠、可拖动调整宽度的面板做 Chat-to-SQL，默认本地 Ollama、也可配置

      设置窗口「AI」分区配置服务地址/模型/API Key（本机加密）；会话按工作区保存，支持多段历史切换与新建（搜索、滚动分页）；标题默认取首条消息截取，可在设置里开关 AI 生成标题
- [x] 执行计划：顶栏「执行计划」按当前语句/选区跑 EXPLAIN，结果区展示统一计划树，
      节点按代价着色并显示 rows/actual；支持 SQLite `EXPLAIN QUERY PLAN`、PostgreSQL JSON、
      MySQL JSON/TREE、ClickHouse JSON，解析失败回退原始结果；ANALYZE 每次确认且只允许
      SELECT/WITH；可一键把计划树交给 AI 做诊断
- [x] SQL 错误修复：执行失败横幅点「AI 修复」，把失败 SQL、驱动错误和涉及表结构发给模型；
      结果用 diff 预览，用户点「应用修复」或「应用并执行」才改编辑器；模型没返回 SQL 代码块时明确报错
- [x] 高危 SQL 拦截：本地确定性规则检查 UPDATE/DELETE 无 WHERE、恒真条件、DROP/TRUNCATE；
      默认弹窗提醒，连接档案可开启「高危 SQL 直接阻断」；不依赖 AI，AI 只负责解释
- [x] 安全与收尾（P4）：连接密码 **AES-256-GCM 本机加密**（密钥 `<config>/db-g/secret.key`，

## 构建与测试

```bash
export GO=$GOBIN/go1.27.3
CGO_ENABLED=0 $GO run .     # 交互窗口（本机 cgo 链接有 .sframe 环境问题，统一关掉 cgo）
CGO_ENABLED=0 $GO test -p 1 ./... # 全量（含编辑器与结果网格基准；-p 1 避免并行包争 CPU 导致基准超限）
CGO_ENABLED=0 $GO test ./ui -run 'TestEditor.*Perf' -v   # 只跑编辑器性能基准
$GO tool mygo vet .         # UI 生命周期检查

make release                # 生成 dist/ 下 Windows / Linux 发布二进制（版本号取自 git tag）
```

顶栏「设置」打开独立设置窗口（单例）：编辑器信息（行数/字节/版本）与 3k/12k/100k
演示预设（写入当前激活控制台并立即落盘，性能自测用）。
