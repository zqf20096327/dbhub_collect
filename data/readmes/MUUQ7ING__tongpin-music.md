# 同频 · 音乐歌单分享平台

使用 **openGauss + Flask** 完成的数据库应用实践项目，包含实验一的建模与 SQL、实验二的权限/存储过程/触发器/备份恢复，以及实验三的 Web 应用与报告。

## 功能

- 曲库检索，支持合作音乐人、专辑与独立单曲。
- 注册登录、个人资料、喜欢歌曲和收藏公开歌单。
- 自建公开/私密歌单、收录与移除、顺序调整和分享。
- 歌单数量与总时长统计，基于 Jaccard 相似度的同好与歌曲推荐。
- 管理员维护歌曲、音乐人、专辑，上传/替换音频和 LRC 歌词。
- 站内跨页连续播放、逐行歌词及翻译、点击歌词跳转。

页面采用 Jinja 服务端渲染，JavaScript 负责局部导航和播放器；部署使用 Nginx、Gunicorn 和 systemd。数据库事务、主外键与联合唯一约束保证业务关系一致性。

## 本地运行

需要 Python 3.12、openGauss 5.0.1、ffprobe。请使用自己的数据库与账号，不要将原作者的服务器作为可复用开发环境。

```sh
cd 实验三
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# 修改 DB_USER、DB_PASSWORD、DB_PORT 和 SECRET_KEY
.venv/bin/python run.py
```

访问 http://127.0.0.1:5001 。驱动连接本机回环地址：数据库在本机时设 DB_PORT=26000；远程数据库则先按自己的 SSH 策略建立本地隧道，再填写转发端口。

数据库需先按实验一的 01—06 脚本建立基础对象，再按实验二的说明建立加歌过程和审计触发器，随后按顺序执行实验三的 01、03、04 迁移 SQL。不同步骤有明确的执行身份要求，不要将所有文件在现有数据库上重复运行。数据库所有者 jp 与应用数据库角色 music_web 需由管理员使用自己的密码创建；迁移脚本不保存密码。02 脚本仅在使用 jp 导入曲库、需要序列权限时执行。

数据库可写接口使用专用 music_web 角色。应用用户可通过页面注册；曲库管理员必须由数据库管理员明确设置 app_user.is_admin，注册接口不能授予该权限。没有提供通用默认登录密码。

## 媒体与测试

仓库不含音乐文件、完整歌词、数据库备份或私有配置。准备自己的音频和 LRC 后，可从曲库管理页上传。没有音频的歌曲仍可展示资料，播放器会禁用对应播放按钮。`数据/` 中是歌曲元数据及分类资料。

`tests/` 包含真实 openGauss 集成测试，需先准备独立测试环境与对应权限；部分测试会临时创建和清理用户、歌曲与歌单。不要直接对有重要数据的数据库运行整套测试。

## 部署

[部署配置](实验三/deploy/)是 ECS 实测配置示例，路径默认 /opt/music-platform，数据库端口 26000。使用前调整路径、运行用户、ffprobe、反向代理与服务依赖；Nginx 示例以独立源码安装位置为准。网站当前部署方案使用 HTTP，正式公开运营前应增加 HTTPS。

数据库逻辑备份与媒体目录需要分别备份。本仓库只发布课程自有代码、报告及其配图，不包含教材或下载音源项目。
