**A CLI for schema *change***

**retrofit** checks each schema change, advises on its risks, and records it
or stops it. Given any point in that history, it writes the schema; given
two, the migrations between them, forward and reverse.

No retrofit command connects to a database. It writes SQL; you review it
and apply it.

The [documentation](https://docs.retrofit.sh/current/):

- [Getting started](https://docs.retrofit.sh/current/getting-started/)
- [Concepts](https://docs.retrofit.sh/current/concepts/)
- [Command reference](https://docs.retrofit.sh/current/commands/retrofit/)

The demos at [retrofit.sh](https://retrofit.sh) show retrofit at work.

Report bugs and suggestions in
[Issues](https://github.com/MonotonicHQ/retrofit/issues/new/choose), and
ask questions on [Discord](https://discord.gg/bNQudQDKjg). Report security
vulnerabilities privately, as [SECURITY.md](SECURITY.md) describes.

> **Pre-release.** The SQL that retrofit writes may be wrong, and applying it
> can damage data. Review it before running it against a database you care
> about, and keep backups. Nothing is stable before 1.0.
>
> **Source.** The source is not public yet. The plan is to release it under
> an OSI-approved open-source license before 1.0.

## A quick look

Record a table, rename a column, and write the schema:

```sh
retrofit init
retrofit schema create users
retrofit op add CreateTable people
retrofit op add AddColumn people id bigint identity=by_default
retrofit op add AddColumn people email text not_null=true
retrofit op add AddPrimaryKey people --column people.id name=people_pkey
retrofit op add RenameColumn people.email email_address
```

Each change is appended to the oplog, `users.oplog`. The rename is recorded
against the column's identity, not its name, and comes with an advisory:

```
+ <rename-op>  RenameColumn      users.people.email
warning: apply-risk-rename-in-use: renaming column "users.people.email" breaks readers still using the old name
```

`retrofit snapshot` writes the schema at the head of the oplog:

```sql
CREATE TABLE "users"."people" (
    "id" bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    "email_address" text NOT NULL,
    CONSTRAINT "people_pkey" PRIMARY KEY ("id")
);
```

## Install

Releases are built for Linux with glibc 2.34 or later (Ubuntu 22.04, Debian
12, RHEL 9 and newer) and for macOS 13 Ventura or later, on amd64 and arm64.
Other platforms, Windows included, have no release build.

retrofit writes SQL for PostgreSQL 15 to 18, and 17 by default. It reads and
writes PostgreSQL 17 syntax, so syntax new in 18 is not supported yet; see
[PostgreSQL versions](https://docs.retrofit.sh/current/postgresql-versions/).

With [Homebrew](https://brew.sh) on macOS:

```sh
brew install MonotonicHQ/tap/retrofit
```

On Linux or macOS, with the install script:

```sh
curl -fsSL https://retrofit.sh/install | sh
```

The script installs the latest release to `~/.local/bin`, without sudo, and
checks the archive against the release's `checksums.txt` first.

Both install the man pages and the bash, zsh and fish completions.
`retrofit completion <shell>` prints the completion script for bash, zsh,
fish or PowerShell.

The macOS binaries are signed and notarized. Apple is asked to confirm that
on the first run, so that run needs a network connection.

Archives for macOS and Linux are on the
[Releases](https://github.com/MonotonicHQ/retrofit/releases) page.

### Channels

- **Releases** (`retrofit`, versions such as `0.10.0`). A release is a WIP
  build that was chosen and passed the full release checks, rebuilt from the
  same commit. The commands above install the latest.
- **WIP builds** (`retrofit@wip`, versions such as `0.11.0-wip.40`). They are
  published as changes land, once CI passes. The number after `wip` counts
  every build and never resets. Install one to try a fix or a feature before
  it is released, and report issues against the exact version
  (`retrofit --version`).

Before 1.0 neither channel promises compatibility between versions.

### Try a WIP

The two casks conflict, so swap one for the other:

```sh
brew uninstall retrofit
brew install MonotonicHQ/tap/retrofit@wip
```

And back:

```sh
brew uninstall retrofit@wip
brew install MonotonicHQ/tap/retrofit
```

With the install script, pass `--wip` for the newest WIP build, or
`--version` for one release:

```sh
curl -fsSL https://retrofit.sh/install | sh -s -- --wip
curl -fsSL https://retrofit.sh/install | sh -s -- --version 0.10.0
```
