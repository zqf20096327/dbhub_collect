# 切分即时战斗：带在线通关排行榜的策略战斗游戏

一个使用原生 Web 技术实现的四人小队 Boss 战游戏。玩家在暂停时为不同角色规划移动和技能，再通过时间轴观察执行结果；完整对战胜利后，可填写昵称上传通关时间并查看公共排行榜。

## 功能与玩法

- 四名角色：法师、猎人、战士、牧师，各自拥有不同技能。
- 暂停时规划移动、普攻与施法，通过时间轴查看动作安排；Boss 施法开始和结束均自动暂停。
- 五个专项练习关与一个完整对战，包含护盾、范围魔法、旋转斩击、召唤和反击机制。
- 完整对战胜利后显示结算，玩家主动上传昵称与游戏内用时。
- 公共排行榜支持同分并列、失败重试及重复提交去重，成绩在重启后保留。
- 支持手机触摸操作、小屏选关布局和直接显示技能说明。

推荐首次体验：选择“魔法练习” → 用 `1–4` 或角色按钮切换角色 → 点击场地规划移动、选择技能安排施法 → 点击“执行”或按空格继续 → 观察预警和时间轴。右键或双指可取消当前操作，菜单内可展开完整操作说明。

## 技术栈

| 部分 | 技术 | 用途 |
| --- | --- | --- |
| 前端 | HTML、CSS、原生 JavaScript、Canvas 2D | 战斗绘制、时间轴、触摸交互与弹窗 |
| 前后端通信 | Fetch、JSON HTTP API | 对局登记、成绩上传与排行榜查询 |
| 后端 | Node.js 24、内置 `node:http` | 同源页面服务、请求校验与排名接口 |
| 数据库 | SQLite、内置 `node:sqlite` | 对局凭证及通关记录持久化 |
| 测试 | `node:test`、`node:assert` | 接口、排序、重复提交及持久化验证 |

浏览器负责战斗模拟，服务端负责校验上传数据、写入数据库和计算排名；没有额外前端构建步骤或第三方运行依赖。

## 启动

需要 Node.js 24 或更高版本。无第三方运行依赖，不需要安装数据库或运行 `npm install`。

将仓库克隆或下载到任意目录，进入包含 `package.json` 的项目根目录后运行：

```sh
npm start
```

浏览器打开 **http://localhost:3000**。Windows 也可双击 `start-game.cmd`。
直接双击 `index.html` 仍能玩游戏，但不能连接排行榜。

```sh
npm test     # 接口、校验、排序、重复提交和持久化测试
npm run dev # 修改服务端后自动重启；前端修改后刷新浏览器
```

## 排行规则

- 只有“完整对战”击败 Boss 后出现上传表单，练习关和失败不上传。
- 成绩为游戏 `gameTime`，单位毫秒。暂停思考和网页失焦造成的未推进时间不计入，属于游戏内用时，不是墙钟时间。
- 昵称 1–16 字符，无登录。每次通关单独排名，同名不代表同一人，不合并成绩。
- 用时升序，同毫秒并列名次（例如 1、1、3）；并列按提交先后展示。
- 默认显示前 50 条。提交成功后显示当前名次，即使未进入前 50 也能获知排名。
- 本局开始时登记一个随机凭证，24 小时有效。一局只能写入一条成绩；相同内容重复上传返回原成绩。
- 首次登记失败不影响玩游戏，但本局不能上传。已登记的通关成绩在网络恢复后可于结算页重试；离开页面不保留待上传成绩。
- 上传由玩家主动确认，公开昵称、用时和日期；本地仅保存上次使用的昵称。

## 项目结构

```text
index.html              游戏页面、结算与排行榜弹窗
assets/game.js          战斗和时间轴逻辑
assets/styles.css       桌面、触屏和小屏样式
assets/leaderboard.js   上传、失败重试、排行榜展示
server/index.js         启动入口
server/app.js           静态页面和 HTTP API
server/database.js      SQLite 建表与连接
test/server.test.js     后端自动化测试
data/leaderboard.sqlite 首次启动后生成，真实排名数据
docs/screenshots/       README 使用的实际页面截图
scripts/               可选的浏览器流程检查
archive/               本地旧版演示备份，不提交到 Git
```

旧版单文件演示保存在本地 `archive/`，不作为服务器公开页面，也不纳入仓库；新用户只需使用根目录的 `index.html`。

## 提交内容与数据边界

公开仓库包含源码、测试、文档和截图，不包含实际玩家数据库、环境变量文件、私钥或本地编辑器配置。`.gitignore` 已排除这些常见本地文件；它不会撤销已提交的历史记录，因此提交前仍应检查暂存区。

```sh
git status --short
git diff --cached
```

首次运行会创建一个空排行榜数据库，不需要从开发者电脑复制数据。报名所需的姓名和班级请通过指定渠道单独提供，不必写入公开源码。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 存活检查 |
| POST | `/api/runs` | `{ "level": "full" }`，返回 `runId` |
| POST | `/api/scores` | `{ "runId": "…", "nickname": "玩家", "durationMs": 12345, "level": "full", "won": true }` |
| GET | `/api/leaderboard?limit=50` | 名次、昵称、时间、日期、总记录数；limit 为 1–100 |

错误响应为 `{ "error": "说明" }`。服务器使用参数化 SQL、请求大小限制、同源校验和每来源 IP 每分钟 120 次写入限制。昵称在页面中使用文本节点显示。

## 手机上测试与公开分享

默认只监听本机。电脑与手机连同一个 Wi-Fi 时：

```powershell
$env:HOST="0.0.0.0"
npm start
```

手机访问 `http://电脑的局域网IP:3000`，并按需要允许 Windows 防火墙入站连接。

若要给互联网上的朋友共用排行榜，需要把整个项目运行在支持 Node.js 的服务器上，通过 HTTPS 域名访问；仅上传静态 HTML 到静态托管平台无法保存公共排名。

服务器上进入项目目录后，设置 `HOST=0.0.0.0`，根据平台要求设置 `PORT`，执行 `npm start`。为 `DATA_FILE` 指定持久化磁盘路径，通过进程管理服务保持 Node.js 运行，并将 HTTPS 入口转发至该端口。

配置环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务端口 |
| `HOST` | `127.0.0.1` | 公开部署通常为 `0.0.0.0` |
| `DATA_FILE` | 项目下 `data/leaderboard.sqlite` | 可指定持久化磁盘上的数据库路径 |

部署时务必为数据库使用持久化磁盘，采用单实例；否则平台重建实例可能丢失榜单。HTTPS 反向代理应保留原始 Host，以便同源校验正常工作。限流使用直接连接 IP，反向代理后请求可能共享额度。
备份时先停止服务，再复制整个 `data` 目录（含可能存在的 SQLite WAL 文件）。不要把数据库提交进 Git；`.gitignore` 已排除。

## 排行可信度

这是试玩排行榜。游戏在客户端运行，服务端只能检查凭证、字段、重复记录及时间的基本合理性，不能证明玩家确实按原规则击败了 Boss。修改网页或直接调用 API 仍可能伪造成绩。若以后需要正式竞技排名，需要增加服务端重放验证或服务端权威战斗模拟，以及玩家身份体系。

SQLite 使用 [Node.js 内置模块](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)。部分 Node.js 24 版本可能提示实验性警告，不影响本项目启动。
