# Telegram-группы и темы для агента в opencode

![tests](https://github.com/WhiteBite/tg-agent/actions/workflows/ci.yml/badge.svg)

Read-only связка: **Telethon (твой аккаунт) → локальный SQLite → MCP-сервер → агент**.

Главная идея — **агент видит не всё подряд, а только то, что ты отметил сам**.
Тем может быть десятки, в каналах — годы переписки; вываливать это в контекст
бессмысленно. Поэтому:

1. ты выделяешь нужное (папка в Telegram **или** точечно темы через `watch.py`),
2. это синхронизируется в локальный индекс (инкрементально, старая история — чанками),
3. агент получает 19 read-only инструментов, которые знают твои алиасы и «что нового с прошлого раза».

## Быстрый старт: одна команда

```bash
python3 start.py
```

Она сама решает, что нужно: нет ключей — спросит и запомнит; не залогинен —
покажет QR; дальше открывает визуал в браузере, где всё остальное мышкой:
**「＋ из Telegram」** — список чатов прямо из Telegram (форум/группа/канал,
пометка «в индексе»), фильтр, окно дней и кнопка «Слить»; **★** — отдать тему
агенту. Ни флагов, ни имён чатов, ни запоминания команд.

Всё описанное ниже — те же шаги, но вручную, для тех, кому нужен точный контроль
(в терминале есть и запасной выбор чатов: `python3 start.py --cli`).

## Как «визуально выделить нужное»

### Вариант 0 — рабочее пространство в браузере

```bash
python3 ui.py                 # http://127.0.0.1:8899
```

Главный экран **«Требует внимания»** показывает просрочки, блокировки, открытые
вопросы и непроверенные выводы. Разделы «Проекты», «Задачи», «Решения», «Вопросы»
ведут к карточке с историей и сообщениями-доказательствами; «Загрузки» —
раздел скачивания и пересылки медиа: задания, файлы, пересылки, подборки.
Тёмная тема по
умолчанию, светлая и системная доступны в настройках; мобильная компоновка —
без постоянных трёх колонок переписки.

- таблицы с фильтрами проекта, ответственного, статуса и срока, сортировкой и пагинацией;
- статус «К распределению» (`backlog`) и вид «Согласование» (`approval`) доступны в фильтрах и правке карточки;
- единый поиск по сущностям и сообщениям (FTS5 с безопасным LIKE-фолбэком),
  фильтры периода/проекта/человека, история поиска и локальные сохранённые представления;
- ручное исправление полей и проверка с аудитом; устаревшая версия карточки
  отклоняется с 409, новые события вновь требуют проверки;
- изменения проекта используют event-id и отдельную явную отметку просмотра:
  она не меняет `watch.last_read` и не подтверждает правильность извлечения;
- настройка привязки синхронизированных тем к проекту и ручной справочник людей;
- раздел «Переписка»: дерево чатов/тем, watch, алиасы, закрепление, отметки
  прочтения, дата, FTS, загрузка старых сообщений и копирование выдержки для агента;
- синхронизация и добавление чатов из Telegram запускаются только по нажатию,
  идущую синхронизацию можно отменить (`POST /api/sync/cancel`);
- раздел 101 показывает только локальное состояние и запросы-кандидаты. Он не
  выполняет авторизацию, проверку сети или отправку и не двигает курсоры экспорта.
- кнопка «Разобрать» в переписке открывает сводку одной темы: записи, пробелы,
  дайджесты и свежие сообщения; страница адресуется по chat_id/topic_id —
  по этой же ссылке её открывают внешние клиенты.
- «Сервисы» — сервисы, триалы и промо одной строкой на сервис: жив или истёк,
  ближайший срок, из скольких чатов всплывал; быстрые действия прямо в строках
  реестров (проверено / закрыть / отложить на неделю), «Закрыть протухшие триалы» —
  массовое закрытие; звёздочка-избранное с фильтром «только избранные» (избранное
  всплывает наверх), недельный фильтр `catalog?due=upcoming`;
- на главной счётчик «Истекает» — открытые записи со сроком в ближайшую неделю;
  настройки содержат секцию «Живые алерты» (слова-триггеры и упоминания);
- «Ссылки» — офлайн-сводка по watch-листу: топ упоминаний, публичных ссылок,
  инвайтов (со статусом из кэша) и mega/mailru; «Поиск в Telegram» — глобальный
  поиск публичных чатов (гейт `TG_ALLOW_LIVE=1`,

найденное не индексируется);
- «Демоны» — статус демонов и очередь транскрипции аудио;
- триалы с давно истёкшим сроком закрываются автоматически (событие `auto_close`),
  поэтому просрочка на главной — только живая; очередь внимания не содержит
  ревью-шума, проверка осталась в карточках и фильтрах;
- счётчики тем в переписке показывают «новое с твоего захода», а не всё
  непрочитанное с начала времён: заход в тему ставит визит-курсор.

**Ограничения:** контракт полей задач 101 ещё не подтверждён. Наличие токена или
локального GUID не означает работающую интеграцию. Отклонение записи человеком
является локальной отметкой: экспортёр пока не использует её как запрет отправки.
Настройки уведомлений позволяют посмотреть сводку без отправки; реальные
получатели по-прежнему задаются в `TG_NOTIFY_ROUTES` на сервере.

Выбор пишется в ту же таблицу `watch`, которую читает MCP-сервер, — агент в
opencode видит отметки сразу, без перегенерации конфигов. `watch.py` остаётся
для терминала и скриптов.

Посмотреть без Telegram: `python3 seed_demo.py demo.sqlite && TG_DB=demo.sqlite python3 ui.py`.

### Вариант A — папка в Telegram

В приложении: **Settings → Folders → New folder**, назови например `AI Agent`,
положи туда нужные каналы и группы. Отмечать в коде ничего не нужно — что в
папке, то и читает агент:

```bash
python3 sync.py --folder <id папки>     # id видно в веб-версии Telegram в URL папки
sync.py --dry-run --folder 7            # сначала посмотреть, что попадёт
```

Каналы-вещания из папки берутся автоматически (раз положил — значит нужно).
Пополнять папку можно и без приложения — агенту достаточно попросить:

```bash
python3 folders.py list                                  # папки и их состав
python3 folders.py add --folder 15 --chat @ai_channel    # доложить чат в папку
python3 folders.py remove --folder 15 --chat @ai_channel
```

Создавать и настраивать сами чаты можно из терминала (реальные операции —
только при `TG_ALLOW_MANAGE=1`):

```bash
python3 manage.py create --title "Моя группа"
python3 manage.py edit --chat -1002000001 --title "Новое"
python3 manage.py topic-create --chat @forum --title "Тема"
```

## Релиз-посты и readme тем

```bash
python3 announce.py draft --repo ../tg-agent --tag v0.10.0 --product tg-agent --tpl-out post.yaml
python3 announce.py post --tpl post.yaml --chat @whitebite_devsoft --topic 323 --send --react 🔥 --pin
python3 announce.py readme --topic-title "🪡 Stitch · ядро" --chat @whitebite_devsoft --topic 325 --send
```

Пост собирается из YAML-шаблона: `badge`, `title`, `what`, `inside` (список),
`ps`, `warning`, `links`, `banner`. Баннер рендерится PIL в 1080x720, если в
шаблоне задан. Без `--send` любой режим — dry-run: печатает текст и сохраняет
баннер, к Telegram не обращается. Реальная отправка (кросспост `--also`,
реакция `--react`, пин `--pin`) только при `TG_ALLOW_MANAGE=1`. У MCP-сервера
есть зерцало для агента — инструмент `tg_manage_post`, регистрируется за тем же
гейтом и требует `confirm=True`.

### Вариант B — точечно темы внутри одной группы

Когда группа одна (твоя `AI`), а тем в ней десятки:

```bash
python3 watch.py topics --chat @mygroup      # темы с цифрами: сколько сообщений, закрыта ли
python3 watch.py add --chat @mygroup --topic 123456 --alias "ML-новости" --pin
python3 watch.py add --chat @mygroup --topic 789   --alias "Релизы"
python3 watch.py list                        # что отмечено и сколько там непрочитанного
python3 watch.py suggest                     # топ-тем по активности + готовые команды add
python3 sync.py --watched                    # синхронизировать только отмеченное
```

Алиас — это то, что увидит агент вместо `chat_id=-1001234567890 / topic_id=789`.

Оба варианта совмещаются: папка даёт каналы, `watch.py` — темы внутри них.
