# Hive Memory — 类脑联想记忆库

用神经科学机制做记忆检索的单机记忆引擎：**SQLite + sqlite-vec + bge-m3 本地向量 + 扩散激活（Spreading Activation）**。

核心主张：纯向量库只能回答"哪条最像"（碎片化），联想记忆库回答"**这整件事是什么**"（故事聚合）。同一查询下，纯向量 Top10 散落在多个对话，联想机制能把同一事件链的记忆完整带出。

> 本项目从一套多智能体交易系统中剥离而来，只保留记忆引擎，不含任何业务代码、密钥与个人数据。

## 核心机制

| 层 | 机制 | 说明 |
|---|---|---|
| L1 | **直连激活** | `cos(q, m)` 语义直接命中 |
| L2 | **放电传导** | 种子记忆沿三类边（时序 1.0 / 共现 0.8 / 语义 0.6）向邻居传能量，能量 = 源能量 × 边强度 × hop 衰减，多路径累加 |
| L3 | **相似度门控** | 传导到的每个节点与查询做检测：`gate = 累积能量 × cos`，过阈值的成为新种子继续放电（最多 4 跳） |
| L4 | **用进废退** | 检索命中即强化（strength↑、fire_count↑），检索即学习；长期不回忆按月衰减 |
| 补充 | **横向抑制** | 同轮激活集合内，高能量节点压制语义近邻的低能量者（压制 hub 记忆垄断） |
| 补充 | **不应期** | 已激活节点不再接收下一轮传导（电信号不回退） |
| 补充 | **在线学习（boost）** | `learn_link(query, target, ±δ)` 把"这个查询确认/否认了该记忆"绑定到查询语义向量上——相似问题下增强/压制，无关问题不受影响 |
| 补充 | **灵活遗忘** | 边强度与 boost 按最近使用时间月度衰减，低于下限即遗忘 |
| 存储 | **写入去重** | 新记忆与同域已有记忆 cos ≥ 0.82 → 合并为一次强化，不新增行 |
| 存储 | **概念涌现** | jieba 分词 + 词表，自动长出概念节点并与记忆建联 |
| 召回 | **双通道** | `single` = 放电快通道；`dual` = 快通道 + 联想通道合并（多带出快通道漏掉的记忆） |

## 快速上手

```bash
python example.py
```

或直接使用：

```python
import config, memory as mem, assoc

BEE = "bee_A"  # 一个 bee = 一个独立记忆库（SQLite 文件）

# 写入记忆（自动向量化、语义建联、链延续、去重）
mid = mem.add_memory(BEE, "项目评审定在周五下午，需要提前准备测试报告", domain_tag="work")
mid2 = mem.add_memory(BEE, "周五评审通过了，下一步排期开发", domain_tag="work")
mem.link_chain_sequence(BEE, mid, mid2)   # 时序链：事件先后

# 联想检索（直连 + 放电传导 + 门控 + 横向抑制）
r = assoc.query_flow_v2(BEE, "周五那个评审结果怎么样", k=8, domain_tag="work")
for x in r["top"]:
    print(x["id"], x["score"], f"hop={x['hop']}", x["content"][:40])

# 在线学习：这次检索确认/否认了某条记忆
assoc.learn_link(BEE, "周五那个评审结果怎么样", mid, delta=+0.3)   # 增强
assoc.learn_link(BEE, "周五那个评审结果怎么样", mid2, delta=-0.3)  # 惩罚（相似查询下压制）

# 灵活遗忘（建议低频定时执行，如每月）
assoc.decay_edges(BEE, monthly=0.9, floor=0.05)
```

记忆即检索即强化：命中过的记忆与边会自动微增强度（`reinforce_hits`），配合月度衰减构成用进废退闭环。

## 架构

```
写入:  文本 → bge-m3(Ollama) → SQLite(sqlite-vec)
       ├─ 去重: cos≥0.82 合并为强化
       ├─ 语义边: Top10 相似邻居, 强度=cos×0.6
       ├─ 时序边: 链延续(有向 旧→新, 1.0)
       └─ 概念: jieba 拆词 → 概念节点 + 建联

检索:  查询 → 向量 → ① 直连 Top-K 种子
                     ② 沿边放电传导(≤4 跳, 能量衰减, 多路径累加)
                     ③ 门控: 累积能量×cos > θ → 激活为新种子
                     ④ 横向抑制 + 不应期
                     ⑤ score = cos + λ·E(n) 排序输出

学习:  反馈 → learn_link(±δ, 查询语义 EMA 绑定到记忆)
       周期 → decay_edges(边/boost 月度衰减, 用进废退)
```

## 文件说明

| 文件 | 行数 | 职责 |
|---|---|---|
| `assoc.py` | ~1160 | 联想检索引擎：放电传导/门控/横向抑制/不应期/boost 学习/灵活遗忘 |
| `memory.py` | ~830 | 存储层：SQLite+sqlite-vec、三类建联、去重、概念、裁剪、schema 自动迁移 |
| `discharge.py` | ~290 | 放电检索（快通道） |
| `memory_tool.py` | ~200 | 面向智能体的检索工具（single/dual 双通道） |
| `feedback.py`* | — | 反馈学习回路（异步队列 → learn_link ±δ） |
| `concept_split.py` | ~130 | jieba 概念拆词 |
| `learn_round.py` | ~85 | 学习轮次编排 |
| `embed.py` | ~80 | bge-m3 向量化（含批量与进程级缓存） |
| `forget.py` | ~70 | 遗忘策略 |

\* 剥离时 `feedback.py` 原文件依赖交易模块（行情/API 客户端），未收入本仓库；其学习原语 `learn_link`/`decay_edges` 都在 `assoc.py` 中，`learn_round.py` 给出了无业务依赖的学习回路写法。

## 配置

全部参数集中在 `config.py`（记忆强度上下限、三类边系数、去重阈值、遗忘周期、召回模式等），均有注释。无需任何 API 密钥——向量化走本地 Ollama。

## 参数寻优（2026-09-02，全量库实测）

在 12,638 条真实记忆 / 151,936 条边 / 3,933 个真实问答对上，对联想引擎的 4 个核心参数做了 36 组合网格搜索（200 问搜索集 + 500 问留出测试集）：

| 配置（β_sem/β_cooc/β_seq/α） | Top1 | Top5 | Top10 |
|---|---|---|---|
| 默认（0.7 / 0.15 / 1.2 / **0.2**） | 3.6% | 9.2% | **48.2%** |
| **寻优后（0.7 / 0.3 / 1.2 / 0.8）** | 3.6% | **13.6%** | 47.2% |
| 纯向量基线 | 0.4% | 10.4% | 18.6% |

结论：**调高联想权重（α 0.2→0.8）和共现边系数（0.15→0.3）让 Top5 提升 48%**，Top10 基本持平（-1pp），Top1 不变。已将寻优值设为 `query_flow_v2` 默认参数。注意：本组参数在"短查询×会话型记忆"上调出，换数据分布建议重搜（脚本思路：固定评测集 → 网格 → 留出集终评）。

配套基建：嵌入编码可指向局域网 GPU 机器（`OLLAMA_URL` 环境变量），RTX 4060 实测批量编码 17ms/条，较 CPU 提升 15 倍。

## 实测参考

在 152 条真实记忆、1,544 条边的库上（bge-m3 CPU 向量化）：

- 改述查询（非原文）Top1 命中率 3/3，语义理解而非关键词匹配
- Top12 结果中 9 条来自联想传导（hop 1~4），3 条为直连
- 一次 `learn_link(-1.5)` 即把目标记忆压出 Top6，且只影响相似查询
- dual 比 single 多带出 3 条快通道漏掉的记忆
- 单次查询延迟：快通道 ~2.3s，双通道 ~4.5s（瓶颈在 CPU 向量化，GPU 可大幅降低）
