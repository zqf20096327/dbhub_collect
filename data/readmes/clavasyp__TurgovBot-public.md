# TurgovBot

Telegram-бот и API юридического помощника для ролевых GTA5-проектов: Majestic RP,
GTA5RP, RMRP, «Россия Онлайн». Знает законодательную базу каждого сервера, отвечает
на вопросы со ссылками на статьи, помогает составлять жалобы и процессуальные
документы, обслуживает десктоп-оверлей и сайт.

*A Telegram bot and backend API that acts as a legal assistant for Russian-speaking
GTA5 role-play servers: per-server law knowledge base, cited Q&A, document drafting,
and article search for a desktop overlay.*

## Возможности

- **Вопросы по законам сервера.** Законы парсятся с форума проекта. Модель-маршрутизатор
  выбирает нужные кодексы, Gemini (Vertex AI) отвечает по ним со ссылками на статьи.
- **Поиск статей для оверлея.** Гибрид без LLM в рантайме: полнотекстовый поиск
  PostgreSQL, триграммы, словарь сленга и синонимов, векторы локальной модели
  FRIDA в pgvector. Нормы ранжируются взвешенным RRF.
- **Ролевой помощник** (адвокат, прокурор) с картой дела и историей.
- **Документы:** жалобы, исковые заявления, уголовные дела, разбор чужих жалоб.
- **Анализатор пробелов в законах** — фоновая очередь с кэшем.
- **Голос:** распознавание речи (Google Speech-to-Text) для голосовых вопросов.
- **API для клиентов:** вход устройства через Telegram (device-code flow, JWT),
  лицензии, веб-вход сайта через Telegram Login Widget.

Десктоп-оверлей и сайт живут в отдельных репозиториях.

## Архитектура

Всё поднимается через Docker Compose (`docker-compose.yml`):

| Сервис | Что делает |
|---|---|
| `db` | PostgreSQL 16 с pgvector |
| `migrate` | Alembic-миграции (`alembic upgrade head`) перед стартом |
| `bot` | Telegram-бот, `main.py` (python-telegram-bot 22) |
| `api` | FastAPI, `api/main.py` — эндпоинты оверлея, поиска законов, сайта |
| `law-embedding-worker` | Фоновый расчёт векторов статей локальной моделью FRIDA |
| `parser-worker` | Парсер форумов на Playwright, `parser_worker/worker.py` |
| `flaresolverr` | Прохождение Cloudflare-проверки для форумов, которые за ней |
| `caddy` | TLS и реверс-прокси перед API, раздача обновлений оверлея |

Основной код:

```
main.py, user_handlers/, admin_handlers.py   Telegram-бот
api/                                         FastAPI: роутеры, схемы, безопасность
services/                                    бизнес-логика: QA, поиск законов, каталог,
                                             эмбеддинги, лицензии, документы
parser_worker/, knowledge_base_manager.py    сбор законов с форумов
law_sources_data.py                          список проектов, серверов и разделов форума
prompts.py, prompts_qa_v2.py                 промпты моделей
alembic/                                     миграции БД
scripts/                                     обслуживание: сборка каталога, бэкапы, смоук-тесты
tests/                                       pytest
```

## RAG, векторы и поиск по законам

С законами работают четыре связанных механизма:

- **Ответы в Telegram:** маршрутизатор `gemini-3.1-flash-lite` выбирает кодексы,
  `gemini-3-flash-preview` читает их целиком.
- **Векторный RAG** для советов оверлея, Q&A v2 и ролевого помощника: фрагменты до
  1200 символов, эмбеддинги `gemini-embedding-001` (3072 измерения) в pgvector
  `halfvec` с HNSW. Найденные фрагменты собираются обратно в целые статьи.
- **Поиск статей без LLM в рантайме:** каталог статей, офлайн-синонимы от Gemini,
  полнотекстовый поиск PostgreSQL, триграммы, сленговая карта и локальная модель
  [FRIDA](https://huggingface.co/ai-forever/FRIDA) (1536 измерений). Результаты больше
  десятка «ног» сливаются взвешенным Reciprocal Rank Fusion. Векторы голосуют, только
  когда корпус сервера посчитан полностью.
- **Защита от порчи данных:** неполный обход форума не удаляет законы, ID статей
  сохраняются при пересборке, каждая нога поиска сообщает свой статус.

Подробно, с моделями, порогами и весами — [docs/RAG_AND_SEARCH.md](docs/RAG_AND_SEARCH.md).

### ⚠️ Незаконченное: смысловой валидатор v3

Синонимы для поиска пишет LLM, и иногда она выдумывает: «может» превращает в «обязан»,
меняет местами суд и полицию, теряет условия. Мы начали строить детерминированный
валидатор, который пускает в базу только то, что доказуемо есть в тексте статьи.
Он разросся до одного файла на 61 502 строки и 65 тысяч строк тестовых матриц. Выдумки
он ловит, но отвергает 39% честных синонимов, и до прода не дошёл. Что получилось,
что измерено и почему остановились — [docs/ENRICHMENT_V3.md](docs/ENRICHMENT_V3.md),
код — в папке [experimental/enrichment-v3/](experimental/enrichment-v3/). Этот код ботом не используется.

## Быстрый старт

Нужны Docker с Compose, проект в Google Cloud с Vertex AI и бакетом Cloud Storage,
бот от [@BotFather](https://t.me/BotFather).

```bash
cp .env.example .env          # заполнить токен бота, БД, секреты
mkdir credentials             # положить JSON-ключ сервис-аккаунта GCP
docker compose up -d --build
```

Имена GCP-проекта, бакета и файлов ключей задаются в начале `config.py`.
Обязательно задайте в `.env` `DEVICE_JWT_SECRET` (длинная случайная строка):
без него токены устройств подписываются случайным ключом процесса и не
переживают рестарт, а веб-вход выключен.

Пошаговая инструкция с миграцией существующей базы, бэкапами и автодеплоем —
[STARTUP_GUIDE.md](STARTUP_GUIDE.md).

Векторный поиск статей включается только когда модель FRIDA разложена в `./models`
на хосте (`LAW_CATALOG_EMBED_ENABLED=true`). Без неё поиск работает в режиме
`keyword_only`.

## Тесты

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt pytest pytest-asyncio
.venv/bin/python -m pytest -q tests
```

Тестам не нужны ни база, ни облако: внешние вызовы подменены.

## Безопасность

Секреты (токены, ключи сервис-аккаунтов, пароли) в репозиторий не попадают:
они лежат в `.env` и `credentials/` на сервере. Об уязвимостях сообщайте
по инструкции из [SECURITY.md](SECURITY.md), не через публичные issues.
