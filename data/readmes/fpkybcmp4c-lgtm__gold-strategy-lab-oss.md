# 黄金 · 三个月策略验证

一个供个人独立运行的中文交易验证工作台，用同一套账户账本记录黄金、纳指和 BTC，分别评估策略表现、交易执行与风险纪律。交易、每日复盘、设置和截图保存在自己的电脑或服务器中。

本项目提供源码与本机服务，不提供公共交易网站、公共注册平台、行情订阅或自动下单。首次启动为空白数据环境，无需任何私人网站账号、云端数据库或 API 密钥。

## 安装与启动

需要 [Node.js 24 LTS](https://nodejs.org/en/download) 和 pnpm 11.25.0。先安装 Node.js，再在终端运行：

```text
node --version
npm install --global pnpm@11.25.0
pnpm --version
```

从 GitHub 的 **Code → Download ZIP** 下载并解压。GitHub 解压目录通常名为 `gold-strategy-lab-oss-main`；可以将它重命名为 `gold-strategy-lab`，再按下面的路径示例操作，也可以直接进入原解压目录。确认当前目录中能看到 `package.json`，不要停留在它的上一级目录。使用 Git 克隆时，可运行 `git clone <仓库地址> gold-strategy-lab` 指定目录名。下载源码不包含运行时依赖，首次安装需要联网访问 npm 软件包仓库。

Windows PowerShell：

```powershell
cd C:\你的目录\gold-strategy-lab
Copy-Item .env.example .env
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

macOS Terminal：

```sh
cd /你的目录/gold-strategy-lab
cp .env.example .env
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

浏览器打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。服务固定监听本机 `127.0.0.1`。保持终端运行，按 `Ctrl+C` 正常停止。开发者可使用 `pnpm dev`，日常使用建议按上面的构建和启动步骤运行。

SQLite 数据表与附件目录由程序首次使用时自动初始化，不需要安装数据库服务，也不需要手工执行 SQL。停止、重启或重新构建程序不会清空记录。

> 基线版本已通过 Windows 与 macOS 15 Intel 云端验收。当前安全修订升级至 Zod 4.6.6，本机 251 项测试、类型检查、正式构建和 HTTP 验收通过，依赖审计为 0 告警；当前提交的云端结果应查看 Actions，不能用旧版本结果代替。Apple Silicon、macOS 桌面界面和 Safari 尚未验证，具体环境与证据见[验收报告](docs/验收报告.md)。

## 第一次使用

1. 进入“设置”，修改验证开始和结束日期；初始日期与本金仅为通用示例参数。
2. 填写自己的账户本金、风险预算、G1 / 非 G1 规则、纪律评分参考线和样本目标。
3. 在多品种配置中核对交易代码、结算币种、每价格点对应金额、数量步进、手续费与滑点。纳指期货与纳指相关代币的合约乘数不同，不能混用。
4. 新增交易，填写计划及实际开平仓事实，再进行每日打卡。缺失的合约、费用、风险或结构信息应保留未知，核实后补录。
5. 在记录与分析页面查看资金曲线、账户回撤、周期收益、R、纪律与模型表现。

Demo / 示例模式使用程序生成的虚构数据，与正式数据分开，不会写入正式交易账本。退出示例模式后仍是自己的记录。

## 可以做什么

- 记录黄金、纳指、BTC；按品种筛选，并支持同一 USD 账户的多品种统计，本金只计一次。
- 保留 G1、S1、S2、L1、L2 等模型分类，以及 G1 / 非 G1 的框架、方向和入场结构记录。
- 记录分批开仓、加仓、分批平仓、手续费、成本、净盈亏、原始风险与 R；计划预览和实际成交分开。
- 每日快速打卡、详细复盘、草稿恢复、历史记录、纪律评分、情绪和精力记录。
- 周度、月度收益、资金曲线、账户回撤、模型及结构分析、机会研究与月度评估。
- 编辑交易、查看修订历史、移入回收站与恢复；保留原始计划和入场风险快照。
- 上传与管理本地交易截图，导出 CSV、JSON 与复盘文本，进行完整备份和恢复。

详细范围、计算口径和边界见[功能说明](docs/功能说明.md)。本项目是研究与记录工具，不提供投资建议、自动交易或收益保证。

## 数据存放与配置

`.env` 为可选配置，默认值即可本机运行；配置示例见 [.env.example](.env.example)。

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | 本机访问端口 |
| `DATA_DIR` | `./data` | 本地数据目录，相对项目根目录或使用绝对路径 |
| `NEXT_TELEMETRY_DISABLED` | `1` | 关闭框架遥测 |

默认数据目录包含 `journal.sqlite`（记录、设置、修订历史和草稿）、`attachments/`（截图）以及运行锁。SQLite 可能同时产生 `-wal` / `-shm` 文件，运行中不要单独复制、移动或删除这些文件。

`.env`、数据库、数据目录、截图、备份、日志和构建产物均不应进入 Git。自定义数据路径时，应选择仓库外的目录；`.gitignore` 无法自动识别任意自定义目录。此应用没有账号隔离或静态数据加密，能够使用本机或读取数据目录的人也可能访问交易记录。请使用自己的操作系统账号和设备权限保护数据。

## 导出、备份和恢复

页面 CSV / JSON 导出用于查看或进一步分析。完整 JSON 含交易与截图元数据，但不含截图原图；原图可从详情单独下载。**要完整恢复程序，请使用下列整套备份。** 页面导出文件不是整套备份恢复命令的输入。

所有命令在项目根目录执行。先在服务终端按 `Ctrl+C` 停机，再备份到仓库外一个尚不存在的目录：

```text
pnpm backup -- ../gold-backup-demo
```

备份是文件夹，含 `manifest.json`、`journal.sqlite` 和 `attachments/`；请保留整个文件夹。建议为每次备份使用独立名称，并定期在另一目录验证恢复。

在新安装中，先完成依赖安装，保持服务停止，然后恢复：

```text
pnpm restore -- ../gold-backup-demo
pnpm build
pnpm start
```

若目标数据目录已经存在，默认拒绝覆盖。确认要恢复到该目录时使用：

```text
pnpm restore -- ../gold-backup-demo --replace
```

`--replace` 会保留原目录为 `data.before-restore-...` 一类名称；自定义 `DATA_DIR` 时名称随目标改变。确认恢复结果后再自行管理旧副本，程序不会自动删除它。备份、旧副本和导出文件都含个人数据，请妥善保存，不要提交到公开仓库。

## 在自己的服务器运行

服务器同样使用 Node.js 24 和上述安装步骤，保持服务监听 `127.0.0.1`。从自己电脑建立 SSH 隧道：

```text
ssh -N -L 3000:127.0.0.1:3000 your-user@your-server
```

然后在自己电脑访问 [http://127.0.0.1:3000](http://127.0.0.1:3000)。这需要你自己的 SSH 账号；与本项目作者的服务没有关系。此版本不支持直接暴露公网端口或配置公共用户登录。端口被占用时，可以在服务器的 `.env` 中改为其他端口，并同步修改隧道的目标端口。

## 验证与故障排查

```text
pnpm test
pnpm typecheck
pnpm build
pnpm security:scan
```

- **提示 Node 版本不符或 `node:sqlite` 不可用**：确认 `node --version` 为 24.x；重开终端，避免仍使用旧版 Node。SQLite 的实验性提示本身不表示失败。
- **Windows 提示不允许运行脚本**：在同一命令提示符中使用 `pnpm.cmd`，或在 PowerShell 将命令写为 `pnpm.cmd install --frozen-lockfile` 等。
- **端口已被占用**：停止旧服务，或修改 `.env` 中 `PORT` 后重新启动，使用对应的 `127.0.0.1` 地址。
- **无法保存或数据库只读**：确认项目与 `DATA_DIR` 位于当前账号可写的位置，不要放在只读压缩包、系统保护目录或同时同步的网络目录。
- **提示正在运行，不能备份/恢复**：先正常停止服务；不要在仍有进程运行时删除运行锁。异常断电后先确认程序已完全退出，再按错误提示处理。
- **有记录但总览为空**：核对验证日期、品种、模型及其他筛选条件，确认处于正式模式；期外记录仍保留。
- **手续费、净收益或 R 显示未知**：核对合约乘数、结算币种、费用和初始风险。系统不会把未知值自动记作零；部分平仓也不能直接算作完整交易 R。
- **页面提示来源无效**：使用启动时显示的 `http://127.0.0.1:端口`；不要换成第三方域名、局域网 IP 或公网反向代理。
- **截图丢失**：确认恢复的是包含 `attachments/` 的完整备份，且 `.env` 指向正确数据目录。
- **安装下载失败**：检查网络和软件包仓库连接，保留锁文件后重试；不要为解决安装问题提交 `.env`、数据库或令牌。

提交问题前请阅读 [SECURITY.md](SECURITY.md)。只提交清理后的复现步骤或虚构样本，不要上传真实交易、截图、完整日志或备份。

## 升级与维护

升级前停止服务并完整备份。保存自己的 `.env` 与数据目录，在新版本安装锁定依赖、运行测试与构建后启动；先在备份副本上验证迁移、截图与金额，再用于日常记录。不要把较新版本的数据库直接交给旧版本运行，回退应恢复升级前的完整备份。

依赖升级必须同步锁文件、第三方许可记录和回归测试，尤其核对合约、费用、R、统一账户和回撤口径。配置中的合约参数需要由使用者根据自己的实际产品核验；项目不自动下载行情或交易所规则。

后续跨平台验证优先补齐 Apple Silicon 与 Safari，并在使用者自行安装的操作系统上按教程完成一次人工安装与备份恢复。
