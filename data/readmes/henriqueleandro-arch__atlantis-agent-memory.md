# Agent Memory — Atlantis University × PingCAP

Student projects demonstrating what an AI agent can do when it **remembers** what happened yesterday, versus when it starts from zero every morning.

## What you are building

A **demonstration of value**: a small, working thing where the difference is obvious to someone who has never seen the product.

The spine of every demo is the same:

> **Run it twice — once without memory, once with — and show the difference.**

That contrast is the deliverable. Everything else is presentation.

## What this is *not*

- Not a benchmark or a load test
- Not an attempt to find the limits or failure modes of the product
- Not a security, compliance or audit assessment
- Not anything involving real customer data — every dataset here is invented

A narrow demo that works cleanly and is well presented is worth more than an ambitious one that half-runs.

## The two scenarios

### Nova Marketplace — a large e-commerce platform

Thousands of engineers use AI coding agents every day across hundreds of repositories. Every morning each agent starts from nothing: it doesn't know the team's conventions, the decisions made last week, or why a piece of code looks the way it does.

Demonstrations to build:

1. **The overnight test.** Work with an agent on a small project, close the session, come back and ask a follow-up. Without memory it's lost; with memory it picks up where you left off.
2. **Across two tools.** Teach an agent something in one tool, ask about it from another. One shared memory, two front ends.
3. **The new teammate.** A second person's agent joins and already knows the conventions the first person established.
4. **Look inside.** Show what the agent actually remembered. People trust memory far more when they can see it.

### Meridian Financial — a retail bank

A customer-facing assistant where a Supervisor agent routes each request to a specialized domain agent — Service, Investments, Cards. Short-term memory holds the current conversation; long-term memory holds what the bank knows about the customer.

Demonstrations to build:

1. **The hand-off.** A customer asks about a charge, then about investments. Without memory they explain themselves twice. With memory, the second agent already knows.
2. **The returning customer.** Come back a week later. The assistant remembers the open issue instead of greeting a stranger.
3. **Surviving a restart.** Stop the assistant mid-conversation and start it again. The thread continues.
4. **What do we know about this customer?** A simple screen showing what the platform remembers and where each fact came from.

## Getting started

Read **[SETUP.md](SETUP.md)** — creating your own free TiDB Cloud Starter cluster and running your own mem9 instance against it.

Everything you need is free and self-service. Nobody has to give you an account or an API key.

## How to submit work

You don't need to be invited to anything. Everything here works through **fork and pull request**:

1. **Fork this repository** to your own GitHub account (the *Fork* button, top right).
2. In your fork, create your team's folder under `teams/` — see [teams/README.md](teams/README.md).
3. **Open a draft pull request early — in your first week, not your last.** It can be almost empty. This is how we see what you're working on, and how you get feedback while there is still time to use it.
4. Keep pushing to your fork; the pull request updates itself. Mark it ready for review when it's done.

Keep every change inside your own team folder. Don't edit another team's work.

## Ground rules

1. **No credentials in this repository.** No passwords, connection strings, API keys or tokens — not in code, not in notebooks, not in screenshots. Use a `.env` file; it is already gitignored.
2. **No real company names anywhere.** The scenarios are invented accounts and must be referred to only as *Nova Marketplace* and *Meridian Financial*.
3. **No real customer data.** Every dataset here is synthetic and generated by you.

This repository is public. Assume anything you commit is permanent and visible to everyone.

## Getting help

Support is real but not instant — the PingCAP people helping carry full customer workloads. Before asking:

1. **Try it yourself first.** Most blockers here are solved by the documentation and an hour of persistence.
2. **Batch your questions** rather than sending them one at a time.
3. **Ask on the pull request or in the shared channel**, not by direct message — so anyone can pick it up and other teams see the answer.
4. If something has blocked you for more than a day, say so clearly **and say what you already tried**. That gets a fast answer.
