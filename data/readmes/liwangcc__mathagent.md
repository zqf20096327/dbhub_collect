# MathAgent

面向数学教师的私有部署智能批阅工作台：导入试卷或答题卡，完成模板确认、学生 OCR、数学判分、教师复核、统计和报告导出。

官网：<https://www.mathagent.com.cn>

> **一句话**：同一张卷配一句「转录这份试卷」，原图 50 次里 46 次把学生的错答 `4√5` 直接写成正确答案 `4/5`，50 次没有一次如实；把印刷题干差分掉之后 50 次全部如实。试过的提示词都没压到 0，去掉题干是这组实验里唯一做到 0 的改动（单卷单题，每组 50 次）—— [证据与 200 条原始回执](evidence/03_prompt-context-leak/)。

> 当前行为以源码、`config.py`、测试和实际运行回执为准。

## 能力

- 详细批阅：模板/版面确认、身份门控、OCR、判分、复核、归档与报告。
- 模板链路：单栏、双栏、三栏处理；教师确认后的题目、作答位和几何才可进入学生批阅。
- 教学与学情：班级管理与风险分组、成绩报告、家长信专属链接、题库与待入库答案、出题练习与原题订正卷、课件库、教师助手（见总览第 6 节）。
- 识图办公：`/api/vision-office`，在配置完整时由教师助手读取模板并生成办公文件。
- 可选桌面节点：只做图像预处理；模型凭据、最终校验和成绩写入仍在服务器。

答题卡路由已注册，但 `ANSWER_SHEET_GRADING_ENABLED` 默认关闭；未完成真实学生答题卡验收前，不把它当作默认生产主链。

## 核心问题：模型会把学生的错误答案改成正确答案

这类产品最致命的失败不是判错，而是**把错的判成对的**：分数好看了，教师看不出问题，学生也拿不到真实反馈。整个架构的取舍都围绕这一点。

用同一张卷、同一道题（学生写 `4√5`，标准答案 `4/5`）、同一模型，只换输入和提示词，各跑 50 次（[`evidence/03_prompt-context-leak`](evidence/03_prompt-context-leak/)）：

| 输入 | 提示词 | 写成正确答案 `4/5` | 写成 `4√5/5` | 抄 `4√5` 但加注「应为4/5」 | 如实只抄 `4√5` |
|---|---|---|---|---|---|
| 原图（含印刷题干） | 「转录这份试卷。」 | **46 / 50** | 2 | 0 | **0**（另 2 次没给答案） |
| 原图（含印刷题干） | 「转录这份试卷，不要看题干，不要计算，直接转录。」 | **33 / 50** | 2 | 2 | 2（另 11 次没给答案或只抄题干） |
| 原图（含印刷题干） | 只要求输出作答 JSON（无防猜规则） | 0 | 8 | 0 | 42 / 50 |
| **差分图（题干已被减掉）** | 同一句「转录这份试卷。」 | **0 / 50** | 0 | 0 | **50 / 50** |

另一轮实验（[`evidence/01_difference-vs-raw`](evidence/01_difference-vs-raw/)）用生产提示词（含「题干、标准答案和数学知识不能作为转录依据」）：原图 6/10 读成 `4√5/5`，差分 0/10。

结论：**提示词只改变概率，试过的 3 种都没压到 0；去掉题干是唯一做到 0 的改动**。原图与差分的差距是显著的（同一句提示词，原图 50 次无一如实、差分 50 次全部如实，Fisher 单侧 p≈1×10⁻²⁹）；但样本只有单卷单题，0/50 的 95% 置信上限约 5.8%（连同 01 的两路差分合计 0/70，上限约 4.2%），只能说「这道题上没再出现」，不能说发生率为 0。生产链路用模板差分而不是原图，目的不是让图更清楚，而是让印刷题干在输入阶段就不存在——模型没有可借用的上下文，只能认字，判断完全回到识别能力上。

**就算将来模型不再被题干带偏，差分仍然划算**：同一句「转录这份试卷。」，原图平均输出 2556 字符、21.5 秒，差分平均 468 字符、5.0 秒——输出短约 5.5 倍，耗时约 4.3 倍（50 次的中位数是 2302 → 501 字符、20.2 → 4.3 秒，口径一致）；换成生产提示词也是 18.6 秒 → 8.2 秒（2.3 倍，01 的汇总均值）。模型不用读题干，也不用把题干再抄一遍，速度和 token 都省在这一步。

这条结论决定了架构顺序：教师确认模板 → 差分只剩笔迹 → 转录只看笔迹 → 判分只接收文本（`text` 阶段显式拒绝图片）。证据里还记录了反例：残留的印刷虚线会把连写的 `ab` 拆成 `a,b`，所以差分后还要抹虚线（见 [`evidence/01_difference-vs-raw`](evidence/01_difference-vs-raw/)）。

## 当前模型职责

| 阶段 | 默认路线 | 约束 |
|---|---|---|
| 学生卷 OCR | Qwen `qwen3.8-flash`（DashScope 按量） | 官方双参数关闭思考；只忠实转录，9000-token应用预算不变 |
| 模板分栏 | Qwen `qwen3.8-flash`（DashScope 按量） | 分栏使用官方关闭思考组合；本地证据与教师确认仍是闸门 |
| 模板目录/解题 | Qwen `qwen3.8-max`（Token Plan） | 题目几何、作答位和独立解题的权威阶段；严格接收 |
| 数学判分 | Qwen `qwen3.8-flash` | 当前唯一数学判分路线；选择题保留机械比对 |
| 知识点分类 | Qwen `qwen3.8-flash` | 只发文字题干与本学段目录；与 OCR/判分共用 Flash 预算 |
| 识图与报告 | Qwen `qwen3.8-flash`（DashScope 按量） | 识图、名单图片识别与学生/批次报告文字；与 OCR/判分共用 Flash 预算 |
| 教师助手 | 服务器 `TEACHER_LLM_*` 配置（部署方自行指定兼容端点） | 聊天与办公助手；截图以多模态 part 直接交给该模型（原生视觉），不经 OCR 转写 |

DeepSeek、YS、MiMo（判分、识图、报告）与旧模板多池不是当前活动路线。`OCR_TEMPLATE_GPT_*` 一类历史变量名仅为兼容保留，与实际调用的厂商无关；不能据此恢复旧路由。

## 实测证据

`evidence/` 里是可复算的原始数据（脱敏输入、模型原始回执、对照表、复算方法），不是宣传截图。下面三行来自 25 道题、每题 10 次的对照实验（`evidence/01_difference-vs-raw`）：

| 实验 | 转录准确率 | 说明 |
|---|---|---|
| 原图直接转录 | 243/250 = 97.2% | 不使用模板差分的基线 |
| 模板差分转录 | 245/250 = 98.0% | 改答案型错误 **0/10**（原图 6/10） |
| 差分 + 抹掉残留虚线 | 249/250 = 99.6% | 当前默认预处理 |

**这些数据显示**（单卷、每路 10 次）：模板差分减少了印刷体残影对转录的干扰，「把题目里的 A 抄成 B」这类会改变答案的错误在差分两路 20 次中为 0；判断题号与作答位之后，手写漏符号时判分仍给出 37 correct / 5 partial / 0 wrong，且没有把读错的作答判成正确。

**「模型把学生答案改对」已经实测到，而且试过的提示词都只压低概率、没有压到 0**（`evidence/03_prompt-context-leak`，同一张原图、同一道 Q21，学生故意写 `4√5`、标准答案 `4/5`，每种提示词各 50 次）：

| 条件 | 写成标准答案 `4/5` | 保留学生原答案 |
|---|---|---|
| 裸提示词「转录这份试卷。」 | **46 / 50** | 0 |
| 灰提示词「转录这份试卷，不要看题干，不要计算，直接转录。」 | **33 / 50** | 2（都加注「应为4/5」）；另 2 次 `4√5/5`、11 次没给答案 |
| 结构化 JSON（无防猜规则） | 0（8 次 `4√5/5`） | 42 / 50 |
| 生产提示词（含「题干不能作为转录依据」；01 的另一轮实验） | 0（6 次 `4√5/5`） | 4 / 10 |
| 差分图（题干已被减掉）+ 同一句裸提示词 | **0 / 50** | 50 / 50 |

其中一次裸提示词的输出直接把学生的 `4√5` 换成 `4/5`，另一次先抄了 `4√5` 又自己补一句「此处手写答案有误，应为 4/5」。

**这不是提示词不够严**：生产提示词已经写明「题干、标准答案和数学知识不能作为转录依据」，仍然有 6/10 读成 `4√5/5`；反过来，不含任何防猜规则、只要求输出 JSON 的提示词是 8/50——每格 50 次仍然分不清提示词之间谁更好（95% 区间互相重叠），能确定的只是原图配哪种都不是 0。提示词只改变发生概率，**这组数据里唯一做到 0 的是让模型看不到题干**——差分把印刷题干减掉，模型没有可借用的上下文，只能认字，判断因此完全落在识别能力上。

**结构上的三道闸（前两道是代码与输入约束，不是统计结论）**：
1. 转录输入用差分图而不是原图，印刷题干在输入阶段就不存在；
2. 判分阶段只接收转录文本，`services/flash_grading.py` 对 `text` 阶段显式拒绝任何图片输入，判分模型看不到原始笔迹；
3. 差分后仍残留的印刷虚线也要抹掉（`99.6%` 那一路），因为残留线条同样会提供可借用的上下文。

每次调用的 token 用量（供应商回报值，不是估算）在 [`evidence/04_usage-cost`](evidence/04_usage-cost/)；价格随供应商、区域、缓存命中率变，仓库不写死——读者按自己拿到的价目表代入 `compute.py`。用阿里云 Token Plan 订阅的走 [`token-plan.md`](evidence/04_usage-cost/token-plan.md)，那里是 Credits 口径：按当前实测用量，一次整班批阅（两页模板 + 50 名学生）约 166 Credits；按量价 ¥1.6–2.2、按 ¥139 档折合约 ¥0.5。

## 架构

```text
Vue 3 / 可选桌面端
        │
        ▼
FastAPI(app.py) ── routers/ ── services/ ── SQLite
        │                         ├─ Redis（生产协调/限流）
        │                         └─ 模型兼容端点
        └─ desktop/worker：图像预处理，服务器验证后消费
```

后端默认监听 `127.0.0.1:8080`；前端开发服务器默认 `5173`，Vite 将 `/api`、`/uploads` 代理到后端。生产由后端服务 `frontend/dist/`。

## 本地开发

准备 Python 3.11+、Node.js 18+。真实密钥只放本地 `.env` 或受保护部署环境，不提交 Git。

```bash
# Python 环境（已有 venv_local 时跳过创建）
python -m venv venv_local
./venv_local/Scripts/python.exe -m pip install -r requirements.txt

# 前端依赖与开发服务器
cd frontend
npm install
npm run dev
```

另开终端启动后端：

```bash
./venv_local/Scripts/python.exe app.py
```

核心批阅链路只装 `requirements.txt`。教师的「办公助手」是可选组件，装在
`requirements-optional.txt` 里 —— 它把 certifi/PyJWT 钉在旧版本，和核心依赖互斥，
两个文件不能一起装。

## 部署

**产品定位：一台服务器 = 一个学校，设计寿命三年**（三年到期后整体清理历史数据）。
**硬约束：单实例部署** —— 不要并行运行第二个应用容器，不要 `--scale`。
SQLite（`data/mathagent.db`）是唯一事实源，学生卷图片在 `uploads/`，两者都是本机磁盘。

### Docker 部署（推荐）

```bash
git clone https://github.com/liwangcc/mathagent && cd mathagent
docker compose up -d --build
# 浏览器打开 http://<服务器IP>:8080
```

`ALLOWED_HOSTS` 默认是 `*`，所以按 IP 直访就能打开；配了域名就在 `data/.env` 里写 `ALLOWED_HOSTS=math.example.com`，否则 Host 校验会返回 400。

首次启动会自动完成三件事：建库、生成 `JWT_SECRET`（写入 `data/jwt_secret`，之后重启沿用，
不会重新生成把所有人踢下线）、生成管理员初始密码（`docker compose logs app` 首次启动时打印，
同时以 0600 权限写入 `data/.first-run-password`；登录后请立即改密）。

模型密钥在库里是 **AES-GCM 加密存储**（`enc:v1:` 前缀），主密钥来自环境变量
`MODEL_KEY_MASTER` 或首次启动生成的 `data/.model_key_master`。**备份 `data/` 时必须连
`.model_key_master` 一起备份**，否则已保存的 Key 无法解密，需要在设置页重新填写。

- **没有阿里云短信账号也能用**：默认 `SMS_ENABLED=0`，登录页只保留密码登录。管理员登录后到
  「系统设置 → 教师账号」给老师建号（手机号可留空，系统会生成一个 199 开头的登录账号），
  把「登录账号 + 初始密码」交给老师即可。
- **批阅密钥**：登录后到「系统设置 → 模型密钥」，简单模式只填两个槽——「模板定位与解题」和
  「学生卷转录与批阅」；展开专家模式才需要分三个职责组单独配置。每个职责只用一把密钥：
  同一厂商按出口 IP 限流，多把同厂商密钥共享同一配额，要提速请向厂商申请更高并发配额。
- **worker 数**：容器内 `GUNICORN_WORKERS` 固定为 1 或 2。验证码票据与微信 OAuth state 只存在
  `data/auth_tickets.db`（SQLite，同机所有 worker 共用一个文件）；登出黑名单与限流计数在 Redis /
  SQLite 共享存储里。两个 worker 不会出现「A 签发、B 校验失败」。
- **Redis 只存易失状态**（限流计数、进行中的租约），
  不是数据源。Redis 数据全丢只影响进行中的操作，不影响成绩与档案。
- **备份**：`data/`（含 `.model_key_master`）与 `uploads/` 必须一起备份；`redis-data/` 只存易失状态，
  可以随时丢弃。建议先停应用再打包，避免拷到写了一半的 SQLite 文件：

  ```bash
  docker compose stop app
  tar czf mathagent-backup-$(date +%F).tar.gz data uploads
  docker compose start app
  ```

- **恢复**：解压回原目录后启动即可。`data/.model_key_master` 丢失时，已保存的模型密钥无法解密，
  需要到设置页重新填写——这也是它必须跟库一起备份的原因。
- **忘记管理员密码**：

  ```bash
  docker compose exec app python scripts/set_admin_pwd.py
  ```

  启动流程只在「没有管理员」或「管理员没有密码」时写入初始密码，已有密码**不会**被 `.env`
  的 `ADMIN_PASSWORD` 覆盖——所以改 .env 等它自动还原是无效的，请用上面的命令显式重置。

想改端口、开短信、配微信登录时，把变量写进 `data/.env`（容器启动时会读取，格式为简单的
`KEY=VALUE`），再 `docker compose up -d`。

## 数据与安全

学生图片、姓名、成绩和导出文件属于敏感教育数据。上传、下载、分享、导出和节点任务都必须保留认证、教师归属、路径安全和服务端最终校验。身份、方向、几何、答案或评分证据不确定时 fail-closed，进入教师确认，不静默生成正式成绩。

请先阅读 [贡献指南](CONTRIBUTING.md) 和 [安全说明](SECURITY.md)。

自建实例的学校还需要阅读 [隐私说明](PRIVACY.md)：学生姓名、试卷照片和成绩属于未成年人个人信息，
部署方是法律意义上的个人信息处理者，删除与访问控制的责任在部署方。
