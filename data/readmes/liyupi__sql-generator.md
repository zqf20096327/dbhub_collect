## ✨ 项目简介

结构化 SQL 生成器（SQL Generator）是由 [程序员鱼皮](http://dogyupi.com/) 开源的一款轻量级纯前端在线工具，能够通过编写结构化的 JSON 模板，自动展开并生成完整的复杂 SQL 语句。访问在线地址 [http://sql.yupi.icu](http://sql.yupi.icu) 即可在浏览器中直接使用，也可以先观看 [项目介绍视频](https://www.bilibili.com/video/BV1qa411J7vh/) 快速了解演示效果。

这个工具诞生于真实的大数据离线分析工作场景。在日常数据仓库与报表开发过程中，开发者常常需要编写长达上千行甚至三千行的超长 SQL 来完成多维度统计，这些 SQL 中往往充斥着大量高度相似却又略有差异的子查询逻辑。手工复制粘贴不仅耗时费力，一旦底层表的过滤条件或关联字段发生变更，就需要逐处排查修改，非常容易遗漏出错。结构化 SQL 生成器正是为了解决这一痛点而设计，它允许你将 SQL 像撰写文章大纲一样拆分组织，同时也完全可以当作通用的「重复代码生成器」来使用。

## 🌟 核心特性与优势

将零散冗长的 SQL 片段抽离为可复用的 JSON 规则后，整个编写、调试与阅读体验都会发生明显变化。下面从解决的核心问题和工具本身的能力两个层面介绍本项目的亮点。

在日常开发与维护层面，你可以把复杂的 SQL 编写逻辑进行结构化拆解，像梳理文章大纲一样自顶向下地组织与阅读查询语句。对于多次出现的公共子查询或计算逻辑，整个模板中只需要编写一次，后续业务口径调整时只需要修改一处定义即可全局生效。除此之外，你还可以针对局部规则进行独立传参和调试，并通过调用树与替换过程视图清晰地追溯每一段 SQL 的引用层级，从而更快地分析和理解复杂查询。

![结构化 SQL 生成器调用树与变量替换过程分析截图](./doc/assets/invokeTree.png)

在交互体验与解析能力方面，工具内置了基于 Monaco Editor 的在线编辑器，同时支持 JSON 模板和生成结果 SQL 的语法高亮、语法校验、一键格式化、查找替换以及代码块折叠，整体编辑手感接近主流桌面 IDE。解析引擎除了支持一键生成完整 SQL 之外，还完整实现了参数透传与嵌套传参机制。例如当你编写 `@a(xx = #{yy})` 时，外层传入的 `yy` 变量会自动透传给 `@a` 规则；当你编写 `@a(xx = @b(yy = 1))` 时，系统也能够正确识别括号层级并将子查询的结果作为参数继续传递。由于解析器并不会强行限制 JSON 规则中书写的内容格式，这套模板语法同样适用于生成重复的业务代码、配置片段或其他文本内容。

## 📖 入门与复杂示例

为了让你更直观地体会结构化编写带来的变化，我们先来看一个简单清晰的基础案例，再进一步拆解真实数仓场景中的多维度复杂报表需求。

### 基础示例：复用相似子查询

假设当前有一个需求，需要计算 `id = 1` 和 `id = 2` 两位同学的身高差。传统手写方式写出来的 SQL 通常如下所示：

```sql
select (s1.height - s2.height) as 身高差
from 
(select * from student where id = 1) s1,
(select * from student where id = 2) s2
```

仔细观察不难发现，上述语句把 `student` 表查询了两次，除了筛选条件中的 `id` 取值不同之外，其余查询结构完全一致。如果未来学生表需要补充过滤状态或者增加关联字段，这两处子查询都必须同步修改，维护成本会随着子查询数量成倍增长。

切换到本工具后，你只需要编写下面这段简洁的 JSON 模板，工具就会自动展开并生成完整的 SQL 语句：

```json
{
    "main": "select @身高差() from (@学生表(id = 1)) s1, (@学生表(id = 2)) s2",
    "身高差": "(s1.height - s2.height) as 身高差",
    "学生表": "select * from student where id = #{id}"
}
```

借助类似「函数调用 + 动态传参」的组织方式，我们彻底消除了重复书写相同子查询的负担，而且从入口 `main` 一眼就能看清整条 SQL 的主干意图。

### 复杂示例：多粒度统计与同环比离线分析

上面的入门案例只是牛刀小试，在真实的大数据离线分析、Hive 或 Spark 数仓开发场景下，单条查询语句往往复杂得多。假设现在需要用一句 SQL 查出下面这张多维度交叉汇总表：

![复杂多维度统计与同环比报表需求示意图](./doc/assets/complex-example.png)

仔细拆解这张报表，会发现它集中了离线数仓 SQL 中几乎所有令人头疼的难点。首先，汇总行与明细行的统计粒度并不一致，而且分类列中不同行之间存在数据交叉，因此无法直接用简单的 `group by` 一步区分，只能拆分为多个查询再做 `union`。其次，报表中的每一列都需要多张底表共同 `join` 计算得出，不同分类行可关联的表集合还不尽相同（图中灰色区域表示无法关联），必须对缺失字段进行补齐，否则无法满足 `union` 的列对齐要求。再加上不同行的同一列计算公式存在差异（蓝色区域）、不同列的过滤范围也不统一（例如最后两列墨绿色需要查全校数据，而其余列只查 1 年级数据），并且最终还要计算同环比，只能将两份不同日期的完整查询结果进行关联并错位计算。

如果按照传统方式纯手工拼接，整条 SQL 中仅基础表的 `select` 就会重复出现几十甚至上百次，排查和修改几乎是一场灾难，而这个表格还只是对真实工作需求简化后的版本。借助本工具，你可以把整张报表的业务口径清晰地拆解为下面这份结构化 JSON：

```json
{
	"main": "select (a / b - 1) from (@查整体(date = 今天)) a, (@查整体(date = 昨天)) b",
	"查整体": "@查年级() union @查1班() union @查2班() where date = #{date}",
	"查年级": "@查汇总_性别汇总() union @查汇总_性别分组() union @查汇总_爱好汇总() union @查汇总_爱好分组() union @查汇总_电脑类别汇总() union @查汇总_电脑类别分组()",
	"查汇总_性别汇总": "@查除电脑关联表()",
	"查汇总_性别分组": "@查除电脑关联表() group by 性别",
	"查汇总_爱好汇总": "@查除电脑关联表()",
	"查汇总_爱好分组": "@查除电脑关联表() where 爱好 in (xx) group by 爱好",
	"查汇总_电脑类别汇总": "@查除三连和学习表()",
	"查汇总_电脑类别分组": "@查除三连和学习表() group by 电脑类别",

	"查1班": "@查1班_性别汇总() union @查1班_性别分组() union @查1班_爱好汇总() union @查1班_爱好分组() union @查1班_电脑类别汇总() union @查汇总_电脑类别分组()",
	"查1班_性别汇总": "@查除电脑关联表() where 1班",
	"查1班_性别分组": "@查除电脑关联表() where 1班 group by 性别",
	"查1班_爱好汇总": "@查除电脑关联表() where 1班",
	"查1班_爱好分组": "@查除电脑关联表() where 1班 and 爱好 in (xx) group by 爱好",
	"查1班_电脑类别汇总": "@查除三连和学习表() where 1班",
	"查1班_电脑类别分组": "@查除三连和学习表() where 1班 group by 电脑类别",

	"查2班": "@查2班_性别汇总() union @查2班_性别分组() union @查2班_电脑类别汇总() union @查2班_电脑类别分组()",
	"查2班_性别汇总": "@查除电脑关联表() where 2班",
	"查2班_性别分组": "@查除电脑关联表() where 2班 group by 性别",
	"查2班_电脑类别汇总": "@查除三连和学习表() where 2班",
	"查2班_电脑类别分组": "@查除三连和学习表() where 2班 group by 电脑类别",

	"查所有关联表": "@查信息表() left join (@查三连表()) left join (@查学习表()) left join (@查电脑表()) left join (@查全校信息())",
	"查除电脑关联表": "@查信息表() left join (@查三连表()) left join (@查学习表()) left join (@查全校信息())",
	"查除三连和学习表": "@查信息表() left join (@查电脑表()) left join (@查全校信息())",
	"查信息表": "select 字段 from 信息表 where 年级 = 1",
	"查三连表": "select 字段 from 三连表 where 年级 = 1",
	"查学习表": "select 字段 from 学习表 where 年级 = 1",
	"查电脑表": "select 字段 from 电脑表 where 年级 = 1",
	"查全校信息": "select 字段 from 信息表"
}
```

提交解析后，工具不仅能够瞬间输出完整的目标 SQL，还会同步生成直观的调用树，让每一层的引用关系与展开过程一目了然。

## 📋 语法文档

理解完上面的案例之后，你可以直接把下面这段自带说明的 JSON 代码粘贴到 [在线生成器](http://sql.yupi.icu) 中试运行一次，几秒钟就能完全掌握全部语法规则：

```json
{
  "main": "必填, 代码从这里开始生成, 用 @规则名() 引用其他语句",
  "规则名": "可以编写任意 SQL 语句 @规则名2() @动态传参(a = 求给 ||| b = star)",
  "规则名2": {
    "sql": "用 #{参数名} 指定可被替换的值",
    "params": {
      "参数名": "在 params 中指定静态参数, 会优先被替换"
    }
  },
  "动态传参": "#{a}鱼皮#{b}"
}
```

下表整理了 JSON 模板中各项核心语法元素的作用与优先级规则，方便你在编写复杂模板时随时查阅：

| 语法元素 | 含义与作用说明 |
| --- | --- |
| 对象键（如 `main`） | 定义 SQL 生成规则的名称，其中 `main` 为必填入口，解析器始终从该规则开始展开 |
| 对象值 | 定义具体的生成规则，既可以直接写 SQL 字符串，也可以写成包含 `sql` 和 `params` 的对象 |
| `sql` 字段 | 定义模板 SQL 语句，可以是任意文本片段，例如一组字段列表、一段查询条件、计算公式或完整 SQL |
| `params` 字段 | 定义当前规则层级的静态参数，解析器会优先使用这里的键值替换当前语句中的 `#{变量名}` |
| `#{xxx}` | 定义可被动态替换的变量占位符，优先读取当前层级的 `params`，未命中时则由外层调用方传入 |
| `@xxx(yy = 1 \|\|\| zz = #{变量})` | 引用其他规则并传递参数，参数值同样支持嵌套变量或其他规则调用，多个参数之间使用三个竖线 `\|\|\|` 分隔 |

## 🔧 技术实现与本地运行

为了与 JSON 数据结构保持最自然的契合度，项目核心解析逻辑使用 JavaScript / TypeScript 编写，同一套解析算法既可以直接在浏览器端运行，也能够无缝复用到 Node.js 服务端。考虑到工具本身足够轻量且强调低延迟交互，项目优先采用纯前端架构实现，无需额外部署后端即可离线或在线运行。

### 技术栈概览

| 类别 | 技术选型 | 用途说明 |
| --- | --- | --- |
| 前端框架 | Vue 3 + Vite | 构建响应式单页应用与极速本地开发构建环境 |
| 开发语言 | TypeScript + ESLint | 提供静态类型约束与统一的代码规范检查 |
| UI 组件库 | Ant Design Vue | 搭建简洁高效的表单、布局与调用树展示界面 |

| 容器化部署 | Dockerfile | 支持通过 Docker 快速构建静态前端镜像并部署上线 |

### 核心解析算法说明

解析引擎从输入 JSON 到输出完整 SQL 的核心执行流程分为四个步骤：

1. 将用户输入的 JSON 字符串解析为 JavaScript 规则对象，并校验入口 `main` 是否存在。
2. 从 `main` 入口规则出发，优先替换当前规则对象中定义的 `params` 静态参数，得到当前层级的中间结果。
3. 扫描并递归解析语句中的所有 `@xxx(...)` 引用语法，在每一层递归中均遵循「先替换本层静态参数，再替换外层调用参数」的优先级策略，同时记录完整的调用树与替换明细。
4. 完成全部递归展开后拼接并输出最终的完整 SQL 语句。

在早期实现中，解析器曾尝试采用正则表达式的非贪婪匹配方式来提取规则引用，但这种方式无法正确处理括号嵌套调用。例如面对 `@a(xx = @b())` 时，非贪婪正则会提前匹配到 `@b()` 之后的第一个右括号，将语句错误截断为 `@a(xx = @b()`。为此，项目专门针对括号层级嵌套场景优化了子查询扫描与替换算法，目前已经能够稳定支持包含多层括号与子查询的嵌套参数传递。

### 本地启动与部署

如果你想阅读源码、在本地二次开发或将其部署到内网环境，可以按照以下步骤在本地快速启动项目（需要提前安装 Node.js 环境）：

```bash
# 1. 克隆仓库到本地
git clone https://github.com/liyupi/sql-generator.git
cd sql-generator

# 2. 安装项目依赖
npm install

# 3. 启动本地开发服务器
npm run dev

# 4. 打包构建生产环境产物
npm run build
```

项目根目录同时内置了 `Dockerfile`，需要通过容器在团队内网部署时，直接执行 `docker build` 构建镜像并启动容器即可。

<summary><b>Q2：有没有基于 JSON 模板自动生成 SQL 语句的纯前端开源项目？</b></summary>

在 SQL 专题方向，鱼皮还开源并录制了 [SQL 数据生成平台（SQL Father）实战教程](https://www.codefather.cn/course/1966416608870055938) 与 [闯关式 SQL 自学网项目教程](https://www.codefather.cn/course/1966412848320004097)，前者涵盖可视化建表、模拟数据生成与多种后端设计模式，后者则基于纯前端 WebAssembly 实现浏览器内运行 SQL 闯关。欢迎前往 [编程导航](https://www.codefather.cn) 查看全部原创实战项目与学习路线。

如果你想紧跟 AI 时代、学习如何用 AI 编程高效开发和扩展自己的提效工具，可以免费阅读开源项目 [AI 编程实战指南（liyupi/ai-guide）](https://github.com/liyupi/ai-guide)，也可以访问 [鱼皮 AI 导航](https://ai.codefather.cn) 及 [AI 编程实战课程](https://ai.codefather.cn/course/2087008226460565505) 系统掌握 Vibe Coding 工作流。

完成项目练习后，如果你正在准备求职面试，欢迎到 [面试鸭](https://www.mianshiya.com/) 针对性地刷 Vue、TypeScript、前端工程化、SQL 调优以及算法数据结构高频面试题，巩固技术深度。更多由程序员鱼皮团队整理的开源项目、技术文档与免费学习工具，均可统一在 [鱼皮团队资源大全](http://dogyupi.com/) 中一站式获取。
