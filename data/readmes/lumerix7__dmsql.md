# dmsql

Dameng (DM) database command-line tool, with usage aligned with `psql`.

See the design docs at [`docs/design/`](docs/design/) and the full configuration reference at [`docs/config/`](docs/config/).

## Installation

One-line install (recommended, **copy-style global install - does not symlink the current repo**):

```bash
./install.sh           # interactive confirmation; or ./install.sh -y to skip confirmation
```

The script runs `npm install` → `npm pack` (which triggers a prepack single-file build) → `npm install -g` of the tarball,
and generates the connection config in `~/.config/dmsql/config.json` (from `config.example.json`).

Equivalent manual steps:

```bash
npm install
npm pack                               # prepack auto-builds dist/cli.js
npm install -g ./damengdb-dmsql-*.tgz  # copies the build artifact globally; the command is dmsql
```

> Do not use `npm link` - it would symlink to the source of the current repo. Package name `@damengdb/dmsql`, command `dmsql`.

## Usage (M1)

```bash
dmsql -c "select * from dual"                     # run SQL then exit
dmsql -f script.sql                               # run a script file
echo "select 1" | dmsql                           # pipe stdin
dmsql -U SYSDBA -h 127.0.0.1 -p 5236 -c "..."     # explicit connection params
dmsql --service example -c "..."                  # use a named service
dmsql -c "select * from t" -o out.csv --csv -t    # export CSV (no header row)
dmsql EXAMPLE -c "select 1"                       # positional args [SCHEMA [USERNAME]] (equiv. to --schema/-U)
dmsql EXAMPLE SYSDBA -c "select 1"                # --schema/-U flag takes precedence over positional args
dmsql --service example -l                        # list schemas then exit (DM has no separate database; equiv. to \dn)
dmsql --list-services                             # list configured services then exit (no DB connection; dmsql-specific)
dmsql --completion bash                           # emit the bash completion script then exit
```

### Shell completion (bash)

Shell-level completion (distinct from in-REPL Tab completion): completes flag options at the shell prompt, and, where values are enumerable, completes those too --
`--service <TAB>` dynamically lists the service names from config (invoking `--list-services`, no DB connection), `-P <TAB>` lists the print-option keys,
`-f`/`-o` use filename completion. The flag list is exported by the program itself and stays in sync automatically as options are added or removed.

```bash
# Enable temporarily (current shell)
source <(dmsql --completion bash)
# Install permanently (any one of)
dmsql --completion bash | sudo tee /usr/share/bash-completion/completions/dmsql >/dev/null
dmsql --completion bash >> ~/.bashrc        # then reopen the shell or run: source ~/.bashrc
```

### ⚠️ V$ dynamic views and `$`

`$` is a metacharacter in the shell. **Under double quotes `$version` is treated as variable expansion**, so
`dmsql -c "select * from v$version"` actually sends `select * from v`, raising "invalid table or view name [V]".

Use single quotes or escape it:

```bash
dmsql -c 'select * from v$version'      # recommended: single quotes
dmsql -c "select * from v\$version"     # or: escape the $
```

(The interactive REPL (M3) reads input without going through the shell, so it is naturally immune to this problem.)

## Connection configuration

Connection parameter precedence (high → low, consistent with psql/libpq): CLI flag (`-h`/`-p`/`-U`/`--schema`) > an explicitly selected config-file service (`--service`) > `DM*` environment variables > built-in defaults. When `--service` is not given, `services` is not read; each field is parsed independently.

> **DM has no separate database**: DM is schema-level (like Oracle), and an instance has only one database. Hence psql's `-d`/`DBNAME` concept collapses in dmsql into **schema** -- use `--schema` (or the positional arg). For psql familiarity, `-d, --database` still works, but it warns and maps to `--schema`.

Environment variables: `DMHOST` `DMPORT` `DMUSER` `DMPASSWORD` `DMSCHEMA` (`DMDATABASE` is a compatibility fallback that maps to schema).
The terminal byte encoding defaults to `utf8` (suited to Linux/mac/modern terminals); on legacy Windows cmd (GBK code page) you can preset with `DMSQL_ENCODING=gb18030` (gb18030 is a GBK superset, no character loss; any other encoding supported by iconv-lite works too), or use `\encoding [enc]` to view/switch. **Output** and **non-interactive input** (`-f` scripts / stdin pipes / `\i` includes) all use this encoding -- i.e. a GBK-saved `.sql` script can be run directly with `-f` after setting `DMSQL_ENCODING=gb18030`. Note: REPL **interactive** input is constrained by Node's readline and stays UTF-8 (to type Chinese SQL interactively on a GBK terminal, switch to a UTF-8 terminal, or save the script as `.sql` and use `-f`).

**Password (aligned with psql)**: no plaintext password is accepted on the command line. Resolution order: `-W` forces a prompt > the config-file password of the explicitly selected `--service` > the `DMPASSWORD` environment variable > the `~/.dmpass` file > (when on a TTY) an interactive prompt; `-w` means never prompt.

`~/.dmpass` (modeled on psql's `.pgpass`, with the database segment dropped for DM): each line is `host:port:user:password` (DM has no separate database; passwords authenticate by user and are independent of schema). Fields may use `*`
wildcards, with `\:` `\\` escapes and `#` comments. The file must be `chmod 600` (otherwise it is ignored). Use `DMPASSFILE` to change the path.

Config file: only the global `~/.config/dmsql/config.{yaml,yml,json}` (**YAML preferred**, `install.sh` generates
`config.yaml` by default; aligned with psql's global `pg_service.conf`, no project-level upward lookup). A service is used only when explicitly selected via `--service <name>` or the REPL `\cservice <name>`; to override per-project you can also use `DM*` environment variables / direnv. The REPL startup script reads `~/.dmsqlrc` or `$DMSQLRC`.

**Supported parameters** (named to align with libpq/psql): under `services.<name>`, `host` / `port` / `user` / `password` (optional; prefer DMPASSWORD or .dmpass) /
`schema` (optional, the schema to connect to; DM has no `dbname` field). YAML example (see `config.example.yaml`):

```yaml
services:
  local:
    host: 127.0.0.1
    port: 5236
    user: SYSDBA
    # password: SYSDBA   # optional; more secure via DMPASSWORD / ~/.dmpass
    schema: ''           # optional: the schema to connect to (DM has no separate database)
```

## Interactive REPL (M3)

Running `dmsql` directly (in a terminal, without `-c`/`-f`) enters a psql-style interactive terminal:

```
$ dmsql --service local
dmsql (0.1.0, server DM Database Server 64 V8)
Type "help" for help.
local=# select * from dual;
local=# select 1,           -- multi-line: no ; yet, so the continuation prompt is shown
local-#        2;
local=# \dt                 -- meta-command
local=# \x on               -- expanded display; \timing on shows elapsed time
local=# \c sys              -- switch schema (SET SCHEMA, no reconnect)
local=# \cservice example   -- reconnect via a configured service
local=# \dservice           -- show configured service details
local=# \q
```

A trailing `#` in the prompt means superuser (SYSDBA); an ordinary user gets `>` (aligned with psql). The REPL connects on startup and exits with an error if the connection fails.
`\password [user]` changes a password interactively (hidden input, not recorded in history / not shown on the command line). Tab completion covers meta-commands, table names (after `\d`), and `\pset` keys and values.
`\c [schema [user [host [port]]]]` (aligned with psql): if user/host are unchanged → only `SET SCHEMA` (no reconnect / no password needed); if user/host change → reconnect (password: reused for the same host/port/user, or `.dmpass`, or a hidden prompt); `-` keeps the current value of a field. To switch configured services use **`\cservice <service>`**, and to view service details use **`\dservice [service]`**.

Features: multi-line accumulation (terminated by `;`), Tab completion (keywords / table names / meta-commands / connection aliases),
`~/.dmsql_history` history (default 500 entries, `0` = keep no history, aligned with psql's `HISTSIZE`; tunable via `\set HISTSIZE` / `-v` / `history.size`), `\timing` / `\x` / `\pset` / `\c` / `\cservice` / `\i` / `\e`.
`\ef [func]` / `\ev [view]` edit a function/view in `$EDITOR` (loading the existing DDL, or a skeleton template when no argument is given) and execute on save (aligned with psql; paired with the read-only `\sf`/`\sv`).
General meta-commands like `\dservice` can be used in the REPL or via `-c` / `-f`.
DM-specific introspection: `\db[+]` tablespaces (`DBA_TABLESPACES`/`DBA_DATA_FILES`), `\dp`/`\z [pat]` object privileges (`DBA_TAB_PRIVS`), `\dconfig [pat]` server parameters (`V$PARAMETER`).
DBA troubleshooting: `\sessions[+]` active sessions (`V$SESSIONS`; `+` appends transaction/login/last-activity time), `\locks[+]` locks and blocking (`V$LOCK`/`V$TRX`; by default lists only contended locks and filters out read intent locks; `+` shows all and appends table id/row id/thread).
Input inside the REPL does not go through the shell, so `v$` views are naturally immune to `$`-expansion issues.

Result paging (aligned with psql): on by default, using `$PAGER` (default `less -FSRX`; if it fits on one screen it prints directly without clearing the screen);
`\pset pager off` disables it. No paging during `\o` redirection or `\watch`.
During query execution / fetching in the REPL, pressing `Ctrl-C` closes the current connection to abort the operation; the next SQL reconnects automatically.

PL/SQL blocks (anonymous `BEGIN`/`DECLARE`, or `CREATE [OR REPLACE] PROCEDURE`/`FUNCTION`/`PACKAGE`/`TRIGGER`/`TYPE`)
treat internal `;` as not a statement terminator; they are terminated by a `/` **on its own line** (aligned with DM disql / sqlplus); the same applies to `-c`/`-f`/pipes:

```
local=# create or replace procedure p as
local-# begin
local-#   insert into t values (1);
local-# end;
local-# /                    -- a / on its own line compiles/executes the block
```

The startup script `~/.dmsqlrc` (or `$DMSQLRC`, aligned with `.psqlrc`): its `\pset` / `\set` / `\timing` etc. are executed one by one before entering the REPL.

REPL query buffer and session commands:

```
local=# select * from t          -- multi-line accumulation (no semicolon)
local-# \p                       -- print the current query buffer
local-# \g                       -- execute the buffer (= semicolon); \g file writes to a file; \gx uses expanded display
local=# \r                       -- clear the buffer
local=# \gexec                   -- execute the buffer, then run each resulting cell as SQL in order (metaprogramming)
local=# \gset                    -- write a single-row query result into variables; \gdesc shows the result column metadata
local=# \w buf.sql               -- write the query buffer to a file; \s [file] view/save command history
local=# \o out.txt               -- redirect query output to a file; \o with no arg returns to stdout
local=# \g |wc -l                -- \g/\o support |cmd: pipe the result to a shell command (less/jq/wc)
local=# \prompt 'name: ' n       -- interactively read a line into a variable; \getenv n ENV / \setenv ENV val
local=# \watch 2                 -- re-run the previous query every 2 seconds (Ctrl-C to stop)
local=# \! ls                    -- run a shell command; \cd change directory
local=# \echo done               -- write to stdout; \qecho writes to the query output (affected by \o); \warn writes to stderr (all support -n to suppress the trailing newline)
```

Script flow control `\if`/`\elif`/`\else`/`\endif` (works in both scripts and the REPL; the expression is interpolated via `:var` then parsed as a boolean):

```bash
dmsql -v example=on -f deploy.sql   # select a branch inside the script based on a variable
```
```sql
\if :example
  \echo running the example branch
\elif :sample
  \echo running the sample branch
\else
  \echo running the default branch
\endif
```

`\gexec` uses a result set to generate and run SQL (metaprogramming), e.g. batch-create indexes:

```sql
select 'create index ix_'||column_name||' on t('||column_name||')'
  from all_tab_columns where table_name='T'
\gexec
```

## Meta-commands (aligned with psql)

Backslash meta-commands work in `-c` / `-f` / pipes (they must be on their own line):

```bash
dmsql -c '\dt'                # list tables in the current schema
dmsql -c '\dt sys.*'          # list all tables under SYS (schema.wildcard)
dmsql -c '\dt+'               # tables + comments; \dtS spans all schemas (including system)
dmsql -c '\d sample_table'    # table/view structure: columns + indexes + primary key + foreign keys + check constraints (empty sections are auto-omitted)
dmsql -c '\d user*'           # wildcard: describe each matching table/view one by one (aligned with psql)
dmsql -c '\d+ sample_table'   # the above + column comments
dmsql -c '\dn'                # schemas · \du users · \dv views · \di indexes · \df functions · \ds sequences
dmsql -c '\sv myview'         # view definition source · \sf myfunc function/procedure source
dmsql -c '\l'                 # databases · \conninfo connection info · \? help
```

`\conninfo` / `\?` work without connecting to the database. The client commands `\!` `\cd` `\echo` `\qecho` also work under `-c`/`-f`;
the query-buffer family (`\g` `\gx` `\p` `\r` `\o` `\watch`) is REPL-only.

## Output formats (aligned with psql)

Short flags: `-A` (unaligned), `-t` (data rows only), `-F` (unaligned separator), `--csv`, `-o` (write to a file).

Print options are uniformly set with `-P key=val` (repeatable):

```bash
dmsql -c 'select 1' -P format=json          # aligned|force-aligned|wrapped|unaligned|csv|tsv|json
dmsql -c 'select 1' -P null=NULL            # the NULL display string
dmsql -c 'select 1' -P fieldsep=,           # the unaligned field separator
dmsql -c 'select 1' -P tuples_only=on       # equivalent to -t
dmsql -c 'select ...' -P format=wrapped -P columns=80   # wrap over-wide columns to 80 cols (continuation lines carry a + marker)
dmsql -c 'select ...' -P expanded=auto                  # switch to expanded display automatically when the table exceeds the terminal (\x auto)
```

Precedence: `-P format=...` > `--csv` > `-A` > the default `aligned`.
For terminal display, if the natural width of the default `aligned` exceeds the target width, it automatically falls back to `wrapped` to show the full content; if too many columns make the minimum `wrapped` width still exceed the limit, it falls back to `expanded`. `-o`/pipes do not rewrite by default; you can explicitly use `-P columns=N` to trigger wrapping.
To disable this fallback, use `-P format=force-aligned`.

Table borders/lines (default matches psql):

```bash
dmsql -c 'select 1'                              # default: border=1 ascii (psql's default style)
dmsql -c 'select 1' -P border=2                  # ASCII outer frame +---+
dmsql -c 'select 1' -P border=2 -P linestyle=unicode   # Unicode box ┌─┬─┐
```

## Import/export \copy (M4)

```bash
dmsql -c '\copy sample_table to sample.csv'               # table → CSV
dmsql -c '\copy (select * from t where a=1) to t.tsv tsv' # query → TSV
dmsql -c '\copy sample_table from sample.csv csv header'  # CSV → table (first row is column names)
dmsql -c '\copy sample_table to stdout csv header' > sample.csv # write the query result to stdout
cat sample.csv | dmsql -c '\copy sample_table from stdin csv header'
dmsql -c "\copy t to t.txt csv null 'NULL' delimiter '|'" # NULL placeholder + custom separator
```

Options: `csv`/`tsv`, `header`, `null '<string>'` (written on export / turned into NULL on import), `delimiter '<char>'` (overrides the default `,`/`\t`). `to stdout` / `from stdin` are for piping.

> `to stdout` writes to the "current query output stream": by default that is the process stdout, but if `\o`/`-o` has redirected output, it writes to that file instead (just like ordinary query results); in the REPL, `from stdin` is rejected (it conflicts with readline input) - use a file instead.

## Logical dump dmdump (aligned with pg_dump)

Ships with a standalone executable `dmdump` (same package, multiple bins, like `pg_dump` in the psql world) - it exports a table's structure + data as plain `.sql`, replayed via `dmsql -f` to rebuild, with zero external dependencies (no need for the DM client's `dexp`/`dimp`).

```bash
dmdump --service example                        # all tables in the current/specified schema (DDL+data) → stdout
dmdump --service example -t sample_table        # a single table
dmdump --service example -t 'sample_*'          # wildcard (* → %, ? → _)
dmdump --service example -n EXAMPLE -N SYS%     # include/exclude schema (repeatable)
dmdump --service example --schema-only          # DDL only
dmdump --service example --data-only            # data only (row-by-row INSERTs)
dmdump --service example --target-schema SAMPLE # the script header injects SET SCHEMA "SAMPLE"
dmdump --service example -c --if-exists         # DROP ... IF EXISTS before replay (in reverse order, child tables first)
dmdump --service example --if-not-exists        # CREATE TABLE/SEQUENCE IF NOT EXISTS (idempotent creation)
dmdump --service example --disable-fk           # DISABLE FK before data, ENABLE after (cyclic/self-referencing FKs)
dmdump --service example --copy                 # data via \copy from stdin csv (faster/smaller replay)
dmdump --service example -f backup.sql          # write to a file (-f is the output file)

dmsql  --service sample -f backup.sql       # replay (no dmrestore)
```

- The connection flags and positional args reuse `dmsql` (`-h -p -U -W -w --schema --service` + `[schema] [username]`); the password is likewise never put on the command line.
- Object selection `-n`/`-N`/`-t`/`-T` (all repeatable, with wildcards; `-t` supports `owner.name`); content `--schema-only`/`--data-only`/`-c|--clean`(+`--if-exists`)/`--if-not-exists`/`--disable-fk`/`--copy`/`--owner`/`--target-schema`; output `-f`/`-F plain`/`-v`. Full list: `dmdump -?`.
- **owner**: by default the owner qualifier is dropped (good for migration, in the spirit of `pg_dump --no-owner`); use `--owner` to keep `"OWNER"."TABLE"`.
- **dump defaults are configurable**: a top-level `dump:` in config.yaml (global) or `services.<name>.dump:` (per-service override) can set defaults for `owner`/`clean`/`ifExists`/`ifNotExists`/`disableFk`/`copy`/`targetSchema`; precedence is **CLI flag > service.dump > global dump > built-in default**. To turn one off for a run use `--no-clean`/`--no-owner`/`--no-if-exists`/`--no-if-not-exists`/`--no-disable-fk`/`--no-copy`. Object selection and schema-only/data-only are still specified each time (aligned with pg_dump).
- **`--disable-fk`**: `ALTER TABLE ... DISABLE CONSTRAINT` before data, `ENABLE` after (ENABLE re-validates). Used for **cyclic FKs** (A↔B) and **self-referencing row ordering** (child rows physically ordered before parent rows) that topological sort cannot cover; off by default.
- **`--copy`**: data uses `\copy <table> (cols) from stdin csv` + inline CSV + `\.` (aligned with pg_dump's COPY, single file, faster/smaller replay) in place of row-by-row INSERTs; off by default. Values are converted to CSV text by column type (exact timestamp text, BLOB hex, BIT `0/1`, NULL→`\N`), and replay relies on DM's string-bind implicit conversion. **Limitation**: a text field containing a lone `\.` line or the literal value `\N` conflicts with the COPY protocol (very rare; use the default INSERT for such data).
- Literals are escaped precisely by column type (numbers unquoted / strings quoted / BIT `0/1` / `TO_DATE`·`TO_TIMESTAMP`·`TO_TIMESTAMP_TZ` / `HEXTORAW`); `TIMESTAMP(N) WITH TIME ZONE` preserves fractional seconds and the UTC offset.
- The script header contains **only comments + an optional `SET SCHEMA`** (no `\set`/no timestamp → plain SQL is most portable, and same input gives same output for easy diffing); to make replay "stop on first error" add `dmsql -v ON_ERROR_STOP=on -f`.
- Note that **DM's DDL auto-commits**: a replay containing DDL cannot be rolled back as a whole; only `--data-only` into pre-existing tables can be made atomic with `dmsql -1`.
- Full-schema export (automatic, aligned with pg_dump dumping everything): sequences + tables are **topologically sorted** by FK dependencies (parents created and loaded first) + **user indexes** (`GENERATED='N'`) + **views/functions/procedures/triggers** (`GET_DDL`; views annotated `FORCE`, order-independent; PL/SQL blocks terminated by `/` on its own line; created at the end). See the [design doc](docs/design/06-logical-dump.md).

## Single transaction -1 (M4)

```bash
dmsql -1 -f migrate.sql      # all statements wrapped in one transaction: committed on success, rolled back entirely if any fails (implies stop-on-first-error)
```

## Scripting: variable passing and error control

```bash
dmsql -v env=example -f deploy.sql                  # pass a variable on the command line, referenced in the script as :env / :'env'
dmsql -v ON_ERROR_STOP=on -f migrate.sql            # stop on error (default is to continue on error, aligned with psql)
dmsql -e -f script.sql                              # echo the SQL sent to the server as it runs (to stderr)
dmsql -E -c '\dt'                                   # echo the dictionary SQL generated by \d* (for learning/debugging)
```

**Control variables** (set via `-v`/`--set` or `\set` in the REPL, aligned with psql):

| Variable        | Values                     | Effect                                                                                                          |
|-----------------|----------------------------|-----------------------------------------------------------------------------------------------------------------|
| `ON_ERROR_STOP` | `on`/`off` (default `off`) | `on` stops on the first error; **the default continues on error** (the exit code is still 1). `-1` implies `on` |
| `ECHO`          | `queries`/`all`            | echo the SQL sent to the server (= `-e`)                                                                        |
| `ECHO_HIDDEN`   | `on`                       | echo the dictionary SQL generated by backslash commands (= `-E`)                                                |

> Echo always goes to **stderr**, keeping stdout / `-o` data-only.

## Variables `\set` (M5-a)

psql-style variables, shared by the REPL and `-c`/`-f`. `\set` is a meta-command that only changes local state and is **never sent to the database**.
On the command line use `-v NAME=VALUE` (alias `--set`) to preset, with higher precedence than auto variables.

```bash
dmsql --service local -c '\set q hello' -c "select :'q' from dual"   # string literal: 'hello'
```

Inside the REPL:

```
local=> \set q hello
local=> select :'q' from dual;        -- :'q'  → 'hello' (a SQL string literal)
local=> select :q from dual;          -- :q    → hello (raw text)
local=> select :"USER" from dual;     -- :"USER" → "SYSDBA" (an identifier; reads an auto variable)
local=> \set                          # list all variables
local=> \unset q
```

The three forms:

| Syntax    | Meaning                                                          |
|-----------|------------------------------------------------------------------|
| `:name`   | raw text substitution (left as-is if undefined)                  |
| `:'name'` | wrapped as a SQL string literal (embedded `'` doubled to escape) |
| `:"name"` | wrapped as a SQL identifier (embedded `"` doubled to escape)     |

Auto variables (seeded on connect, re-seeded after a `\c` switch): `USER` `HOST` `PORT` `SCHEMA` (`DBNAME` is a compatibility alias for `SCHEMA`, same value, to ease porting psql scripts).

Interpolation happens **after** statement splitting (split on `;` first, then substitute), so a `;` inside a variable value does not alter statement boundaries;
substitution is lexer-aware and skips single/double-quoted strings and comments (a `:x` inside a string or comment is not substituted).

> ⚠️ DM (Oracle-family) also uses `:name`/`:1` as bind-parameter placeholders, which conflicts with psql's `:name` variable syntax.
> This tool does not currently enable bind parameters; an undefined `:name` is passed through as-is; a variable takes effect only when a variable of the same name exists.
> Use `:'name'`/`:"name"` to avoid ambiguity. `LAST_ERROR`, `\echo`/`\if`, etc. are deferred to later.
