### 关系型数据库

- **云数据库 RDS**：覆盖 MySQL、PostgreSQL、SQL Server、MariaDB，是大多数业务的首选，稳定、兼容性强，新用户价格亲民

简单说：普通 Web 应用、小程序用 **RDS MySQL** 够了；数据量大、高并发上 **PolarDB**；缓存用 **Redis**；大数据分析上 **AnalyticDB**。

## RDS 和 PolarDB 怎么选？搞不清楚的看这里

这是被问最多的问题，我来给你捋一捋。

**选 RDS 的理由：**
- 业务刚起步，流量不大，预算有限
- 需要 SQL Server 或 MariaDB（PolarDB 不支持这两个）
- 对 MySQL 原生生态依赖强，迁移成本敏感
- 团队规模小，不想管太多架构问题

**选 PolarDB 的理由：**
- 读写并发高，单实例压力大
- 数据量级在几十 GB 以上，有增长趋势
- 需要快速弹性扩容计算节点（PolarDB 可以秒级加只读节点）
- 已经在考虑分布式数据库

有一个简单判断方式：如果你的 RDS 实例 CPU 经常跑到 70% 以上，是时候考虑升级到 PolarDB 了。而且 PolarDB 的存储是按实际使用量计费，不是固定购买，对存储需求波动大的业务来说更经济。

**Q：RDS 基础版和高可用版的核心差异是什么？**

基础版是单节点，没有主备切换，适合开发、测试和对可用性要求不高的场景。高可用版有主备两个节点，主节点故障时自动切换，适合生产环境。价格差距在3倍左右。

**Q：PolarDB 分布式版适合什么场景？**

适合数据量超大（TB 级）、写入压力极高、需要水平扩展的场景，比如电商订单系统、金融流水记录。分布式版的管理复杂度也更高，普通业务直接用 PolarDB 标准版就行。
