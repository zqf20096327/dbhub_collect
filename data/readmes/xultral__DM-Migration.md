# 达梦数据库迁移工作台

面向 Windows 的达梦数据库可视化迁移工具。使用 `bin` 中的官方 `dexp.exe`、`dimp.exe` 执行迁移，通过附带的 `dodbc.dll` 读取数据库元数据。

主要流程是 **源库指定表 → 本机转储文件 → 目标库**，可以把源 Schema 中选定的表映射到另一套数据库的目标 Schema。

**[下载最新版本](https://github.com/xultral/DM-Migration/releases/latest)** · **[查看发布记录](https://github.com/xultral/DM-Migration/releases)**

## 下载与选择

当前发布平台为 **Windows x64**，无需安装 Python。Release 提供以下文件：

| 文件 | 包含内容 | 启动方式 |
| --- | --- | --- |
| `DM-Migration-1.0.2-windows-x64-portable.zip` | 程序、完整官方 `bin`、启动脚本和图文说明 | 解压整个文件夹，双击 `DM-Migration-1.0.2.exe`。推荐用于日常迁移与更换官方工具版本。 |
| `DM-Migration-1.0.2-standalone.exe` | 程序及内置的官方工具和依赖 | 单个文件，直接双击；无需另外携带 `bin`。 |
| `DM-Migration-1.0.2.exe` | 仅可视化程序 | 适合已有官方工具的用户，需要在旁边放置完整 `bin`，或在“环境设置”指定工具目录。 |
| `SHA256SUMS.txt` | 各发布附件的 SHA-256 校验值 | 用于验证下载的文件是否完整。 |

便携版的目录结构：

```text
DM-Migration-1.0.2-windows-x64/
├─ DM-Migration-1.0.2.exe
├─ start.bat
├─ README.md
├─ docs/images/
└─ bin/                  保留所有 DLL 和子目录
```

单 EXE 版运行时会先将内置工具解压到临时目录，启动速度和临时空间占用会受完整 `bin` 的大小影响。连接信息和任务记录仍保存在程序旁边的 `data`，转储文件默认写入 `output`；保存设置时不会保存内置工具的临时路径。也可以在旁边放置外部 `bin`，或在“环境设置”切换到其他官方工具目录。

## 启动

双击对应版本的 **EXE** 或 **start.bat**。程序会打开本地浏览器界面，不会打开额外的控制台窗口。

程序所在目录需要可写。使用便携版时，将 EXE 和 `bin` 文件夹放在同一目录；移动程序时一并移动 `bin`，保留其中的配套 DLL、`dependencies` 等子目录。单 EXE 版可单独移动。

从源码启动需要 Python 3.10 或以上，不依赖第三方 Python 包：

```powershell
python -X utf8 app.py
```

界面服务只监听 `127.0.0.1`，默认自动分配空闲端口。关闭浏览器后任务会继续运行；退出程序请使用界面左下角的“退出”。

## 指定表迁移

1. 填写源库和目标库的主机、端口、用户名、密码。达梦默认端口是 `5236`，点击“测试连接”或“连接并继续”。
2. 选择源 Schema，加载实际表清单。支持搜索、批量勾选，也可手动添加表名，每行一个，保留原始大小写。每次任务使用一个源 Schema。
3. 选择目标 Schema 和已有表处理策略，设置需要迁移的内容、并行度与工作目录。
4. 确认范围后执行，查看实时日志。程序先重新验证两端连接、源表和目标 Schema，再导出、导入。

### 1. 连接数据库

分别填写源库与目标库，点击“测试连接”。两端显示“已连接”后，点击“连接并继续”。截图使用本机隔离测试库，端口 `15237` / `15238` 仅用于演示；实际达梦默认端口为 `5236`。

![连接源库和目标库，两端连接成功后进入下一步](docs/images/01-connections.png)

### 2. 选择数据表

选择源 Schema 并加载表清单，勾选需要迁移的对象；右侧展示最终迁移清单。可以搜索表名或注释，也可以手动输入表名。截图中选择了三张表，未选择 `UNSELECTED`。

![选择源 Schema，勾选指定数据表并查看已选清单](docs/images/02-tables.png)

### 3. 设置目标与迁移选项

将源 Schema 映射到目标 Schema，选择已有表处理策略，设置工作目录和迁移内容。默认并行线程数为 `4`，单表导出线程数为 `2`；源库正在处理业务时，可从 `2` / `1` 开始。线程数不会减少转储文件大小。

![设置 Schema 映射、已有表处理策略、工作目录和并行参数](docs/images/03-options.png)

### 4. 执行并检查结果

确认范围后启动任务，依次执行连接验证、`dexp` 导出和 `dimp` 导入。运行日志可以筛选警告与错误、下载保存；任务完成后仍需要核对目标库数据。“完成 · 有警告”表示已完成并存在需要检查的警告。

![查看连接验证、导出和导入的完成状态以及官方运行日志](docs/images/04-completed.png)

目标 Schema 需要事先存在。程序不会自动创建数据库账号、Schema 或表空间。源账号需要有权读取所选表；目标账号需要具备相应建表、写入及对象创建权限。跨 Schema 导入通常需要适当的管理权限。

源库与目标库的地址、端口、Schema 相同时会拒绝迁移，防止误操作同一批表。主机名与 IP 指向同一服务器时，请自行核对目标位置。

## 目标表处理策略

| 策略 | 行为 |
| --- | --- |
| 跳过 `SKIP`（默认） | 保留已有表，仅导入不存在的表。 |
| 追加 `APPEND` | 向已有表加入导出的数据，保留原有行；重复执行可能产生重复行或主键冲突。 |
| 清空后导入 `TRUNCATE` | 清空已有表数据，保留表结构，再导入。 |
| 替换 `REPLACE` | 删除已有表，再导入表结构和数据。 |

清空和替换需要在确认窗口中输入完整目标 Schema，后端也会校验确认内容。迁移前请准备目标库备份；停止任务或导入失败不会自动回滚已经提交的数据。

## 其他功能

- **导出数据**：选择源表，保留 `.dmp` 文件，不连接目标库。
- **导入数据**：选择本机 `.dmp` 文件，填写文件中的原始 Schema，可筛选表，也可导入文件中的全部对象。适用于本工具生成的单文件转储。
- **任务记录**：查看状态、日志和工作目录；复用配置时需重新输入密码。
- **迁移内容**：可控制表数据、索引、约束、触发器和授权信息。默认迁移表数据、索引、约束、触发器，默认不迁移授权信息。
- **环境设置**：修改工具目录，检测官方工具的版本和可运行状态。

表清单中的“统计行数”来自 `ALL_TABLES.NUM_ROWS`，可能过期或为空，不能作为迁移后的精确行数校验。默认不迁移优化器统计信息，迁移后可按需重新收集。

只迁移部分表时，需要考虑外键、引用对象、触发器、授权和表空间的依赖。并行导出期间源库仍可能发生写入；应用不保证跨表事务快照一致性，需要根据业务安排迁移窗口及数据核对。

## 官方工具版本与系统架构

分开 `bin` 的好处是可以独立更新 `dexp` / `dimp` 和驱动版本，减少程序本身的体积，也便于从官方安装包替换整套客户端。替换时保留同版本的 DLL 与依赖目录。

**分开 `bin` 不等于一个 EXE 可以运行在所有系统和架构上。** 当前发布程序为 Windows x64，程序通过进程内加载 `dodbc.dll` 读取元数据，因此驱动必须是 Windows 64 位；官方导出、导入工具也必须能在当前 Windows 环境运行。Linux、ARM64 等客户端平台需要单独适配、构建并使用对应工具，不能仅通过替换 `bin` 获得支持。

源库和目标库所在服务器的操作系统可以与运行工具的电脑不同，通过数据库连接访问即可；仍应确认官方客户端与两端数据库版本、转储格式兼容。当前内置包使用提供的 Windows x64 官方工具，单 EXE 包也固定了这套工具的版本和架构。

## 文件与密码

```text
DM-Migration-1.0.2.exe   可双击启动的程序，使用外部 bin
DM-Migration-1.0.2-standalone.exe  内置官方工具的单 EXE
start.bat                优先启动 EXE，未打包时启动 Python 源码
app.py                   源码入口
dm_migration/            连接、命令构建、任务和本地 HTTP 服务
web/                     中文可视化界面
bin/                     用户提供的达梦官方工具及依赖
data/settings.json       连接地址、用户名和工具目录，不保存密码
data/jobs/<任务编号>/    任务配置与 UTF-8 应用日志
output/<任务编号>/      默认转储文件与官方导出、导入日志
```

每个任务使用独立工作目录，转储文件与日志会保留。导出失败、没有生成有效转储文件或用户停止任务时，后续导入不会启动。官方工具返回退出码 `2` 时，只有日志明确给出对应阶段的“成功终止导出/导入，出现 N 个警告”最终摘要、且没有实际错误信息，才显示“完成 · 有警告”；登录失败、数据错误、没有完成摘要及其他非零退出码仍会判为失败并保留已有文件供排查。

`服务器与文件内数据的 CASE_SENSITIVE 参数不匹配` 表示源库转储文件和目标库对标识符大小写的规则不同。即使导入完成，也应核对表名、列名、约束与实际数据，尤其注意仅靠大小写区分的对象。可在两端分别执行 `SELECT SF_GET_CASE_SENSITIVE_FLAG();` 查看实际配置。工具会保留该警告，不会自动更改数据库大小写规则。

密码保存在当前连接或任务的内存中，通过官方工具的标准输入传入，不出现在子进程命令行、参数文件、配置和应用日志中。界面“记住连接信息”只保存主机、端口和用户名。

直接调用官方 ODBC 驱动，不需要安装或注册系统级 ODBC 驱动。为兼容驱动的连接串解析，登录时会创建一个仅含主机、端口和驱动路径的临时用户级 ODBC 配置，登录后立即删除，不在其中存储密码。

对于中文等非 ASCII 密码，`dimp` 可能使用转储文件的编码接收密码。程序只会在明确的初始登录失败、且尚未开始文件校验或导入时，依据工具报告的 UTF-8 文件编码调整密码输入并重新连接；开始处理导入后不会自动重试。

## 构建与验证

发布构建需要 Python、PyInstaller 和本机对应的官方工具。仅构建使用外部 `bin` 的程序：

```powershell
python -m pip install pyinstaller
.\build.ps1
```

构建脚本先运行自动化检查，再生成单文件 EXE，并复制到项目根目录。`bin` 独立放置，不会打进 EXE。

将完整官方 `bin` 内置到单 EXE：

```powershell
.\build.ps1 -BundleBin
```

生成 `DM-Migration-<版本>-standalone.exe`。构建的是当前 Python、操作系统和架构对应的程序，不支持在 Windows x64 上直接跨平台打出 Linux 或 ARM64 版本。

生成完整便携 ZIP、程序 EXE 和校验文件；加 `-Standalone` 同时生成内置单 EXE：

```powershell
.\package-release.ps1 -Standalone
```

发布附件写入 `dist/releases/<版本>/`。脚本只收集程序、`bin`、启动脚本、README 和文档截图，不会收集连接配置、迁移数据、任务日志或测试数据库。已构建时可使用 `-SkipBuild` 仅重新打包。

发布到 GitHub Release，例如当前版本：

```powershell
git tag -a v1.0.2 -m "Release v1.0.2"
git push origin v1.0.2
$releaseAssets = (Get-ChildItem -LiteralPath 'dist/releases/1.0.2' -File).FullName
gh release create v1.0.2 --repo xultral/DM-Migration --title "DM Migration v1.0.2" --generate-notes @releaseAssets
```

发布命令需要已认证的 GitHub CLI，并具有仓库发布权限。后续发布先更新 `dm_migration/__init__.py` 中的版本号及启动脚本，再使用对应版本的 tag 和附件目录。

自动化检查：

```powershell
python -X utf8 -m unittest discover -s tests -v
```

真实达梦集成检查（需要本项目中的 `dminit.exe`、`dmserver.exe` 等完整官方二进制）：

```powershell
python -X utf8 tests/integration_dm.py
```

集成检查只使用 `testdb` 中创建的三套隔离测试实例，端口为 `15237`、`15238` 和 `15239`，不连接业务数据库。检查包括指定表跨库迁移、Schema 映射、中文与大小写敏感表名、大字段、四种已有表策略、独立导出/导入、特殊字符密码、大小写配置警告的退出码判断、真实主键冲突的失败判断与密码脱敏。退出时停止测试实例，测试文件保留在 `testdb`、`.validation` 和 `output/验证 中文路径`，可在停止实例后删除。

## 常见问题

- **驱动或工具启动失败**：保留与工具同版本、同位数的配套 DLL 和依赖目录。发布程序为 64 位，需要匹配的 64 位达梦客户端。
- **创建 SOCKET 连接失败**：检查地址、端口、服务运行状态及防火墙。端口栏只填数字，地址栏不填 `http://` 或端口。
- **表清单为空**：检查 Schema 的精确名称与读取权限；也可手动添加表名，执行前仍会验证表的可访问性。
- **目标 Schema 不存在**：先由数据库管理员创建所需 Schema，再加载或填写该名称。
- **迁移会占用多少磁盘**：当前先导出本次勾选的全部表，再开始导入。工作目录需要容纳完整转储文件，导入后文件仍会保留；当前没有磁盘余量预警或自动清理。大库建议分批迁移，在核对结果后清理不需要保留的 `.dmp`。单 EXE 版还需要额外的临时解压空间。
- **导入报错**：查看日志中的达梦错误码，检查对象依赖、权限、表空间和目标表结构。转储文件保留，可修复后使用“导入数据”重新处理。
