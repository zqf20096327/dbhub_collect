## 项目简介

**SmartKBS** 把备课出题、课堂互动、练习考试、学情分析、荣誉激励和系统运维收敛在同一套账号体系与数据链路里，供一所学校、一个教研组或一位任课老师直接使用，无需拼装多个工具。

系统**不限定学科**。学科清单、年级、班级、题型、称号、AI 模型与提示词模板全部来自配置（`backend/system_config.json` 与数据库主数据表），切换课程体系只改配置、不改代码；学科的**显示顺序**可在课程中心左侧栏直接拖动（仅管理员，全校生效）。平台自身就是从「人工智能」一门课起步、再泛化为多学科通用版式，因此「零学科硬编码」是落地结论而非宣传语。

系统内置**小学、初中、高中**三个学段的年级与班级主数据（一年级 ~ 高三，共 12 个预置年级），教师可持有「高一|高二」这样的多年级任教范围，所有数据读写按任教范围收口。课程本身同样可以面向多个年级（`高一|高二`），练习提交与资源共享按年级交集放行。幼儿与高校场景没有内置学段规则，需自行扩展年级主数据。

AI 能力经统一调用服务接入，按优先级自动接管、逐级降级：

1. **云端百炼知识库（RAG，第一优先级）** — 知识检索服务就绪时先检索再生成，界面标注引用来源；不可用时自动落到下一级
2. **本地文库（第二优先级）** — 独立知识库模块：Chroma 向量 + FTS 关键词双索引，云端/本地向量模型均可；云端不可用或未命中时补位
3. **直接调用大模型** — 兜底路径，兼容 DashScope 与 DeepSeek

**双引擎**：上述链路的生成步骤可运行在云端（DashScope / DeepSeek）或本地 Ollama，按云端/混合/本地三档切换；云端知识库检索仍走百炼，本地文库可使用云端或本地向量模型（能力矩阵见系统配置）。

**两个维度互不影响**：AI 接入模式（云端 / 混合 / 本地）只决定**生成**走哪个引擎；知识库检索是否生效、是否出网，只由「启用知识库检索」与「向量化通道」决定。因此「本地模型 + 云端知识库」是常规组合（本地生成、云端检索）；要真正离线，关闭云端知识库检索并把向量通道选为本地即可。

教师端各 AI 页面统一显示当前生效的引擎与知识库链路（模型名、云端 / 本地、降级原因），一眼可辨"谁在回答、查没查资料"；学生端不显示。

对话与附件同寿命：提问里上传的图片和文档会跟着对话一起入档，重开历史仍能看原图、下载原件；附件只对本人可见，容量与无引用回收由系统配置统一管理。

## 核心设计理念

- **🧠 AI 原生，但题库优先**
  AI 嵌在出题、批改、答疑、分析、板书的具体环节里，而不是外挂一个聊天框；同时能靠已有数据解决的绝不重复调用模型——出题与组卷一律「题库优先 → 缺口交 AI → AI 生成的题必须入库留用」，让每一次算力消耗都沉淀成可复用的资产。
- **🎯 因材施教 · 千人千面**
  学生端 AI 学伴按自选人格（鼓励型 / 严谨型 / 幽默型）、连续出错的薄弱知识点与学习画像调整回答风格和推荐内容；教师端 AI 助手按任教范围与学科给出备课辅助与学情洞察。
- **🔄 教学闭环 · 数据飞轮**
  学习行为采集 → AI 分析 → 个性化反馈 → 行为改善构成闭环：考试、练习、对话、点名与抽问的数据回流成学生画像，画像再反哺下一轮的 AI 决策与推荐。
- **⚡ 按需调用，无人使用零消耗**
  所有 AI 调用按需触发：精选池用完才补、热点新闻缓存懒加载、AI 摘要不访问不生成、语音合成关闭即零计费。不为闲置算力付费。

**产品特性**

| 特性 | 落地方式 |
| --- | --- |
| 👥 三层角色，各配其 AI | 学生用 AI 学伴陪伴式学习，教师用 AI 助手减负增效，管理员掌握配置与督导，互不干扰 |
| 🏆 游戏化激励 | 12 级称号 + 成就徽章 + 自动积分奖励引擎，把外部压力换成持续正反馈 |
| 🌐 配置驱动 · 学科无关 | 换学科只改配置与提示词模板，无需修改代码 |
| 🔒 本地化优先 | 三个 SQLite 库 + 本地目录存数据，可完全离线部署；AI 走国内可达通道，pip 有镜像方案，学生数据不出校 |
| 📱 零安装多端 | 手机浏览器直接访问，无需 App、无需额外部署 |
| 🖥️ 桌面版一键装 | Electron 壳 + 内置后端与前端产物，目标机器不需要 Python / Node.js |
| ⬆️ 在线增量升级 | Git 部署可站内完成拉取、迁移、依赖安装、重启，失败自动回滚 |
