## 一、取数规则（7 条）——数据从哪来

1. **先盘家底再动手**：仓里 17 项资产（池、解读四层、富集、证据、35,017 篇 README 存档、db_scan、裁决表、出池台账……）先查有没有存货，缺的才去外面找。
2. **每个数字三色标源**：程序读的（能回查到文件和字段）、人写的（判断）、外部查的（标日期）——三色绝不混写。
3. **AI 内容分载体**：精选卡（公众号）卡面零 AI；档案卡只搬 state/interp 已有解读（查表，零模型调用），没解读的仓不补跑、不挂块（2026-11-14 用户裁定）。
4. **外部带进来的事实必须回仓验证**：验证不过就删或改写（本轮处决 3 个：verify 唯一被词频证伪、8KB 无出处、apt 命令无出处；反转 1 个：Crunchy 升一手）。
5. **一个数字只有一个源头**：星数只认池 + 发布日接口；evidence 里的新值只作漂移参考，不混用。
6. **会过期的数字盖"截至"戳**；发布当天三件套（星数/协议/提交日期）重新拉接口覆盖池值。
7. **二手不许升格一手**：找不到一手就老实标"公开资料"。

## 二、内容规则（6 条）——卡上放什么

8. **顺序按读者提问走**：是什么 → 适配谁 → 同类排第几 → 谁在用 → 适不适合我 → 怎么试。
9. **标题用中性词**：解决什么问题、近期动态、生产采用、适用场景——不用口语花活。
10. **文案三删**：内部术语不上卡（db_scan/enrich 留给底稿）、一句话不说两遍、铺垫语全删；证据原文引用也不上卡，只留结论。
11. **填不出用固定降级话术**（"官网占位，命令实跑后回填"），不许编。
12. **卡面形状从简**：头部一行并拢基本数据、不加衍生数（+36、名次条、百分位）；擂台四列（项目/星/简介/相似度）封顶 TOP5；用户说删的就删，不恋战。
13. **删内容要查孤儿**：删页脚别忘了正文里挂着的星号注释这类连带引用。

## 三、算法规则（11 条）——同类擂台怎么选（tools/arena_select.py v2.6）

14. **名单机器圈、层位人来裁**：人只做划掉和捞回，每笔写理由留痕。
15. **分数管门槛，star 管排序**：分数答"领域对不对"，star 答"值不值得上桌"——纯分数排序会被刷满分的小脚本淹没（v1 教训）。
16. **相似度 = 覆盖度**：算"候选干了主角多少活"；候选多出来的专长不扣分（v2.3 错杀 pghoard 教训）。
17. **标签按稀有度加权（IDF）**：越少见越值钱，encryption 比 backup 值钱。
18. **共享标签置信取高的一边（max）**：提取时的不确定不能错杀真同类（barman 0.489→0.627 教训）。
19. **生态专注度**：候选支持一堆库的（通用工具）降分，只做主角这个库的不降（databasus 出局、wal-g 0.78 是真相）。
20. **星门槛 = max(300, 候选集中位数)**：纯百分比会被小仓拖塌，纯绝对值跨领域不可移植。
21. **界面层标签剔除**：候选带 web-console 等而主角没有 → 出局，包装层不跟本体打擂台（pgbackweb 案例）。
22. **AI 类目只当两个角色**：无标签候选的救命稻草（cat_fallback 0.40，v2.3 落地已验证）+ 层位过滤器；绝不当加分项（双重计分教训）。
23. **算法必须落成仓里的脚本**：版本号、参数、输入快照、自检断言、裁决留痕缺一不可——"可复算"不能靠嘴说。
24. **新算法上线两道关**：先消融测试（拆一个零件看名单变不变），再跑三张异类卡试点。

## 四、流程规则（4 条）——怎么干活

25. **一张卡 = 一份 JSON 底稿 + 双出口渲染**（网页/公众号）：图文数字一致靠同源生成，不靠人眼对。
26. **先方案后动手，一次只做一件**；每个工作项自检断言通过才打勾。
27. **试点结果如实报**：算法在标签浓的卡（数据库本体、高可用）一次过零否决；标签薄的卡（工具类）人工否决是常态——卡型决定自动化程度。
28. **盯住"人工否决笔数"这个负向指标**：它上升就是算法退步的信号，该修就修。

## 五、增补规则（14 条）——批量档案管线（2026-11-12~14，gen_cards/build_cache）

29. **提及数 = slug(owner/repo) 整串口径**：README 里出现 `owner/repo` 才算（URL 按相邻对切分、剥 `.git` 尾缀），排除本仓与同 org、仅计池内，≥1 才挂块，截至戳=缓存建成日；精选卡/档案卡/公众号三载体同源同数。弃"裸名+星数门槛"的两条死因要记牢：同名借数（0★ 同名仓借到高星仓的 19,579）、通用词词频（名叫 table/like 的仓数出上万）。
30. **趋势缓存必须在当晚快照 commit 之后重建**：建在快照落盘前永远差一天（11-12 20:38 建缓存 < 当晚 23:55 快照落盘的实测教训）。
31. **近期动态只展 90 天最近一条**：版本剥前缀（`release/2.60.0`、`v2.60.0` → `2.60.0`）+ 日期 + 英文原文首句（≤300 字符截断，原文引用不翻译）；90 天无发布退回单条最新版。
32. **擂台简介列 = 池内 description**（120 字截断），无则退共享标签 → 类目 → "标签覆盖"；esc() 是透传函数，一切外部文本必须 html.escape 真转义（`a<b & c` 上卡教训）。
33. **应用类（judge cat=应用）一个口径三处剔**：不出档案卡（11,923 张已删）、不当擂台主角（无卡可挂）、不当擂台候选。
34. **公众号版「谁在生产用」末条挂程序口径行**：owner/repo 引用数 + 语料数 + 截至日，数字从 mentions.json 直查，与精选卡一致。
35. **相似度封顶 1.0**：覆盖度语义不许超 100%——分子取两边置信之 max、分母只算主角置信，mid×high 组合会冲破 1（v2.5 修，全量实测 19,938 行 >1）。
36. **应用类候选在圈选阶段剔，不在渲染时挖洞**：空出名次由下一名非应用候选补位（react-firebase-starter 出局、piccolo 补位案例）；单跑版与批量版共用 EXCL_CAT 单源常量，行为必须一致。
37. **卡面擂台标签动态读 arena_all.json 的 meta.algorithm**：算法升版本不改出卡代码，标签永不漂移。
38. **局部重跑必须并入全局 manifest**：--fn 跑一张不许把 2 万张的清单覆盖成 1 条（11-13 实际事故）；要无视指纹重写必须显式 --force。
39. **指纹并进 manifest**：条目 {html, stars, fp}，增量比对只读这一个文件（空跑 259.6s → 5.9s）；清单丢失/缺指纹自动回退到重写，永远站在安全侧。
40. **卡指纹 = 生成器版本 + 渲染器版本 + 整卡内容 md5**（剔除 generated_at）：数据或模板任何一边变都触发重写，防"静默不更新"，也防改模板后旧卡残留。
41. **日更三步**：`build_cache --steps all`（快照 blob 全在本地时约 1 分钟：索引 ~14s + 趋势 ~13s + 提及 ~29s）→ `arena_batch`（池/标签/db_scan 变了才跑，~4 分）→ `gen_cards`（全量 30 秒 / 空跑 6 秒）；出精选卡/公众号稿时提及行直查 mentions.json。趋势步突然变慢或 skipped>0，先查当天池快照 blob 在不在本地（blobless 克隆现拉失败会被静默跳过，11-02~04 缺三日教训），别急着优化算法。
42. **出池卡是档案，只搬不删**：退出活跃清单的卡搬 archive/（原卡原样+归档清单记原因/出池日/星数），原因限定出池/GitHub 归档/转应用类，低星未选中不算出池（防 --min-stars 误搬整批）；回池只打 restored_at 标、档案不动；归档只在全量跑做，局部跑不触发。
43. **档案卡解读层四件套 = 查表搬运**：一句话/综述段/亮点/适用场景全从 text 层直读；综述段进简介块，顺序一句话→综述→亮点→适用场景（gen_card v1.5）；再强调 32 条的教训——`esc()` 是透传，综述段等长文本必须 `html.escape` 真转义（自测抓到 `<` 破 HTML）。
44. **无 README 仓走 desc 降级层**：只挂一句话，副标必须写「仅据仓库描述·低置信」（该层置信 low 是层常量）；徽章仍按 judge 层口径显示「未解读」（11-14 用户令：不改）。「未解读」三种实况要分清：desc 已解读（~1,027）/ 判定卷拒收（个位数，不自动重试）/ 无 README 无描述（无资料）。
45. **应用类口径 = is_app 两级**：judge 类目为准，无 README 仓退 desc 层类目；两层都无的（无资料）不算应用照常出卡。
46. **应用类补档**：全量跑时给档案清单里还没有的应用类仓各生成一张档案卡直接落 archive/（清单条目 backfill=true，快照不刷新，之后不跟着日更重写）；GitHub 已归档的仓与活跃卡同口径不补；排在搬迁之后跑，刚搬进档案的不重复生成。
