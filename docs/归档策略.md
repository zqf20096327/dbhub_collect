# 归档策略（档案卡 v1 · 2026-11-15）

> **一句话定位**：什么仓出活跃卡、什么仓进 archive/、每次全量生成时怎么严格校验。
> 判定全部程序化（读 index.json 单一数据源），人只定口径不动名单。

## 一、活跃卡资格（全量 targets 过滤，按序短路）

一个仓要出活跃卡，必须**同时**满足：

| # | 条件 | 判定源（index.json） |
|---|---|---|
| 1 | 在池（index repos 有此 fn） | `repos[fn]` 存在 |
| 2 | GitHub 未归档 | `r.archived != true` |
| 3 | 非应用类 | `is_app(r)` = judge.cat=应用 或（无 judge 时）desc.cat=应用 |
| 4 | 非「其他」类 | `is_other(r)` = 类目（judge 优先退 desc）=「其他」——13 类都不匹配的兜底类（教程/书单/杂项） |
| 5 | README 存档文件存在 | `r.readme_file == true`（build_cache v1.3 起**显式 True/False 都写**；字段缺失=旧缓存，安全侧判"有"） |
| 6 | 内容完整：四块（简介/README首段/能力徽章/适配库）**≥3 块** | `n_blocks(r) >= 3` |
| 7 | 星数 ≥ --min-stars（默认 0=不设限） | `r.stars >= min_stars` |

**设计原则**：
- 条件 5 为 v2 口径（2026-11-15 深夜用户令「只保留完整的，3-4 块」）：纯块数判定，无星数豁免——README 懒得写的大项目（neo4j 本体 1 块）同样归档，数据补齐（tags/dbs 回填）后下次全量自动回池。
- 「其他」类目**不是**归档条件（JavaGuide 等学习资料仓 README 全、块数够，2026-11-15 裁定不动）。
- 应用类口径是"类目"，不完整口径是"内容×人气"，两个维度独立判定、互不包含。

## 二、归档类型（exit_reason，按序归因，先中先归）

| 优先级 | reason | 判定 | 当前规模* | 说明 |
|---|---|---|---|---|
| 1 | `pool-exit` | 不在池 | 22 | 出池台账另有 absent_since |
| 2 | `github-archived` | 池标 archived | 2 | 上游自己删/封 |
| 3 | `app-category` | is_app | 12,213 | 含 11,903 补档 + 搬迁；应用类另走 archive_apps 补档（backfill=true，快照不刷新） |
| 4 | `other-category` | 类目=「其他」 | 1,435 | 2026-11-15 深夜：兜底类目全归（JavaGuide 等教程资料仓） |
| 5 | `no-readme` | readme_file=False | 1,623 | 2026-11-15 口径 A：无 README 文件全归，含 desc 降级层 721 张 |
| 6 | `incomplete` | 块 <3（v2，无星数豁免） | 515+4,044 | 2026-11-15 两轮：先块≤1 且<10 星（515），深夜升纯块数口径（~4,044） |
| — | `below-min-stars` | 只是 --min-stars 没选中 | 0 | **不归档**（防高门槛跑一次搬走 1.9 万张） |

\* 截至 2026-11-15 全量：活跃 19,375 / archive 14,375。

**归档动作**：只搬不删（cards/ → archive/，HTML+JSON 原样），清单记 reason/stars/fp/archived_at/absent_since；回池只打 restored_at 标、档案不动；归档只在全量跑做，局部跑（--fn/--limit）不触发。

## 三、严格校验（gen_cards 全量跑末尾，VERIFY）

全量跑（无 --fn/--limit）在归档步骤之后执行 `verify()`，四项全过才算成功，**任一失败打印明细并 exit 1**（daily_cards 链自动中止，不带病收工）：

| # | 校验 | 抓什么问题 |
|---|---|---|
| V1 | 活跃清单每张卡不满足任何归档条件（is_app / no_readme / incomplete / archived / 不在池） | 过滤逻辑失效、判定函数与统计口径漂移 |
| V2 | 反向：repos 里满足全部活跃条件的仓，一个不少都在清单 | targets 过滤漏仓、index 与清单脱节 |
| V3 | 盘上 cards/ 的 .json 数 == 清单 count | 孤儿卡、清单覆盖事故（11-13 曾发生） |
| V4 | 盘上 .html 数 == .json 数 == 清单 count | 双出口成对完整性（半张卡、错位文件） |
